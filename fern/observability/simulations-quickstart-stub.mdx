In this quickstart, you'll run an AI tester through a real conversation with your assistant and get a pass or fail result, in about 10 minutes. By the end you'll have a reusable simulation suite you can run again after any change.

## What you'll build

A simulation suite that runs a scripted tester — with its own personality and goal — against your assistant or squad, then scores the outcome with an evaluation plan.

## Prerequisites

* A Vapi account.
* At least one assistant or squad to test.
* A [structured output](/assistants/structured-outputs-quickstart) to evaluate the conversation. Simulations require at least one, and you can create it during setup.

The API builds **bottom-up** — create a personality and a scenario, pair them into a simulation, then run it. (The **Dashboard** flow is a convenience layer over these same calls.)

**1. Create a personality**

This request creates a personality — the AI tester's configuration. You give it a name and a full assistant setup (model, voice, and system prompt), which together determine how the tester behaves in the conversation.

```bash
curl -X POST "https://api.vapi.ai/eval/simulation/personality" \
  -H "Authorization: Bearer $VAPI_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "name": "Skeptical caller",
    "assistant": {
      "model": {
        "provider": "openai",
        "model": "gpt-4o",
        "messages": [{ "role": "system", "content": "You are a cautious caller who double-checks details before sharing information." }]
      },
      "voice": { "provider": "11labs", "voiceId": "sarah" }
    }
  }'
```

The response returns the created personality, including its `id`. Save it — you pass it as `personalityId` in step 3.

**2. Create a scenario**

This request creates a scenario: what the tester should try to accomplish, plus the evaluation plan that decides whether a run passes. The `instructions` set the tester's goal, and each item in `evaluations` compares a structured output against an expected value.

```bash
curl -X POST "https://api.vapi.ai/eval/simulation/scenario" \
  -H "Authorization: Bearer $VAPI_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "name": "Book an appointment",
    "instructions": "Book an appointment for next week. Confirm your details when asked.",
    "evaluations": [
      {
        "structuredOutput": { "name": "appointment_booked", "schema": { "type": "boolean" } },
        "comparator": "=",
        "value": true,
        "required": true
      }
    ]
  }'
```

`comparator` accepts `=`, `!=`, `>`, `<`, `>=`, `<=`. To reuse an existing structured output, pass `structuredOutputId` instead of an inline `structuredOutput`.

The response returns the created scenario, including its `id`. Save it — you pass it as `scenarioId` in step 3.

**3. Create a simulation**

This request creates a simulation by pairing a scenario with a personality. It ties together what the tester does (the scenario) with who the tester is (the personality), producing the unit you run against a target.

```bash
curl -X POST "https://api.vapi.ai/eval/simulation" \
  -H "Authorization: Bearer $VAPI_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{ "scenarioId": "<scenario-id>", "personalityId": "<personality-id>" }'
```

The response returns the created simulation, including its `id`. Save it — you pass it as `simulationId` in step 4.

**4. Run it**

This request starts a run against your assistant or squad. You pass the simulation to run, the target to test, the transport (voice or chat), and how many iterations to execute.

```bash
curl -X POST "https://api.vapi.ai/eval/simulation/run" \
  -H "Authorization: Bearer $VAPI_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "simulations": [{ "type": "simulation", "simulationId": "<simulation-id>" }],
    "target": { "type": "assistant", "assistantId": "<assistant-id>" },
    "transport": { "provider": "vapi.webchat" },
    "iterations": 1
  }'
```

Use `"provider": "vapi.websocket"` for voice. To run a suite instead, create one with `POST /eval/simulation/suite` and pass `{ "type": "simulationSuite", "simulationSuiteId": "<suite-id>" }` in `simulations`.

The response returns the run, including its `id`. Save it — you use it in step 5 to check the result.

**5. Check the result**

This request fetches the run's current state. Poll it until `status` is `ended`, then read `itemCounts` to see how many simulations passed or failed.

```bash
curl -X GET "https://api.vapi.ai/eval/simulation/run/<run-id>" \
  -H "Authorization: Bearer $VAPI_API_KEY"
```

The response includes `status` (`queued`, `running`, `ended`) and `itemCounts` (`total`, `passed`, `failed`, `running`, `queued`, `canceled`).
