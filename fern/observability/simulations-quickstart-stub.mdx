In this quickstart, you'll run an AI tester through a real conversation with your assistant and get a pass or fail result, in about 10 minutes. By the end you'll have a reusable simulation suite you can run again after any change.

## What you'll build

A simulation suite that runs a scripted tester — with its own personality and goal — against your assistant or squad, then scores the outcome with an evaluation plan.

## Prerequisites

* A Vapi account.
* At least one assistant or squad to test.
* A structured output to evaluate the conversation. Simulations require at least one, and you can create it during setup.

## Steps

<Steps>
  <Step title="Create a simulation suite">
    Go to **Simulations → Suites** and select **Create suite**. Give the suite a name, then under **Targets** add the assistant or squad you want to test. Select **Confirm**.

    <Note>
      A suite opens in view mode. To change a suite — now or later — open it and select **Edit** in the top right.
    </Note>
    {/* [OK] screen: "Create a new simulation suite" modal — Name + Targets. Edit-to-modify per Stephen. */}
  </Step>

  <Step title="Configure the scenario">
    The suite opens with a first simulation. In the **Scenario** tab, name the scenario and write the **Intent** — what the caller is trying to accomplish. Be specific about the goal.

    {/* [OK] screen: Edit simulation 1 → Scenario tab (Scenario name, Intent) */}
  </Step>

  <Step title="Choose a personality">
    Open the **Personality** tab and pick a preset from **Personality name**, or edit the **Behavior** to describe how the caller acts. Set **Who starts first** to **Tester** or **Target**. Optionally expand **Advanced settings** to set the tester's model, transcriber, and voice.

    <Note>
      A personality is shared. Editing it changes every simulation that uses it.
    </Note>
    {/* [OK] screens: Personality tab (preset dropdown, Behavior, Who starts first, Advanced: Model/Transcriber/Voice) */}
  </Step>

  <Step title="Build the evaluation plan">
    Select **Next**. On the **Evaluation plan** tab, add at least one evaluation: choose a structured output and a comparator to check against an expected value. Create a structured output here if you don't have one yet.

    For this quickstart, add a boolean structured output named `appointment_booked` ("Was an appointment booked?") with the comparator `equals (=)` and an expected value of `true`.

    <Warning>
      A simulation needs at least one evaluation before you can run it.
    </Warning>
    {/* [OK] screen: review step → Evaluation plan tab (Select output… + comparator; Add Evaluation / Create Structured Output) */}
  </Step>

  <Step title="Add variables, tool mocks, and webhooks (optional)">
    On the same review step, use the other tabs as needed:

    * **Variables** — add `Name` / `Value` pairs available to the simulation.
    * **Tool mocks & webhooks** — mock deterministic tool outputs for the target, and toggle **Simulation start** / **Simulation end** webhooks (voice simulations only).

    {/* [OK] screens: Variables tab; Tool mocks & webhooks tab (Add mock; start/end toggles, voice-only) */}
  </Step>

  <Step title="Save and run">
    Select **Save & run**. In **Run suite**, confirm the target, pick a **Mode** (**Chat** is faster and cheaper but skips audio evaluation; **Voice** runs the full audio experience at about 2× the cost), and choose the number of **Iterations** (1, 3, 5, or 10). Select **Confirm** to start the run.

    {/* [OK] screen: Run suite modal (Targets, Mode Chat/Voice + cost note, Iterations 1/3/5/10) */}
  </Step>

  <Step title="Review results">
    Go to **Simulations → Runs**. Your run appears with its **Status** and **Simulation result**, alongside the suite name, iterations, total run items, target agent or squad, and run date. Filter by time range, status, or target to find a run, and select **Re-run** to run the suite again.

    A run moves through **queued**, **running**, and **ended**. {/* [OK] screen: Runs list — status "1 queued" */}

    Open a run to see its detail. The header shows the target, mode, run date, and the overall result (`Passed` or a count such as `1/1 failed`). The **Run items** list on the left has one item per simulation and iteration, each with its own status. Select an item to review it:

    * **Results** — the **Evaluations** panel next to the **Transcript**. Each evaluation shows its name, type, and outcome, for example `appointment_booked` — *Passed. Expected = true and got true.* The transcript lists the conversation turn by turn between the tester and your assistant.
    * **Tools & webhooks** — tool calls and webhook activity for the run item.

    {/* [OK] populated results confirmed from a passing run (PR 15471): boolean eval shows
       "Passed. Expected = true and got true."; transcript is turn-by-turn tester/assistant.
       [PENDING at V&V] voice-run extras: recording playback. Example names cleaned (was "Steve Test"/"My Test"). */}
    Select **Re-run** to run the suite again. {/* [OK] */}
  </Step>
</Steps>
