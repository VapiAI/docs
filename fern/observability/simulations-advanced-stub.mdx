Advanced simulation options let you mock tool responses, trigger webhooks on run lifecycle events, and reuse structured outputs across simulations. Use them once a basic suite runs and you need finer control or automation.

## How it works

Advanced options attach to a simulation on its review step, alongside the evaluation plan. They shape what the target assistant sees during a run and what happens around it, without changing the assistant itself. Open a suite, select **Edit**, then **Next** to reach the review step and its **Evaluation plan**, **Variables**, and **Tool mocks & webhooks** tabs.

## Configure the tester

The tester is the AI caller that drives the conversation, and its configuration lives in the personality. On a simulation's **Personality** tab, expand **Advanced settings** to change how the tester reasons, listens, and speaks:

- **Model** — the provider and model that control how the tester reasons. Use any provider and model you have access to.
- **Transcriber** (optional) — override the audio-to-text provider, language, and model for the tester. Defaults to the assistant's transcriber.
- **Voice** — the provider and voice the tester speaks with. Pick from a configured voice provider or paste a custom voice ID.

Transcriber and voice apply to voice simulations. Chat simulations use the model only.

<Note>
  Editing a built-in **(Default)** personality saves it as a new personality you own; the built-in default is left unchanged. Configuration changes apply to future runs, not to runs that already completed.
</Note>

## Mock tool responses

Mock a tool so it returns a fixed result instead of running. On the review step, open **Tool mocks & webhooks**. Under **Tool mocks**, select **Add**, then configure each mock with three fields:

- **Tool** — pick one of the target assistant's tools from the dropdown.
- **Mock result** — the string returned to the assistant in place of the tool's real output.
- **Enabled** — toggle the mock on or off.

<Warning>
  Simulations do not run real tools. A mock returns a fixed result string to the assistant — the actual tool or API is never called. You cannot exercise real tool behavior in a simulation.
</Warning>

The mock result is plain text. You can enter JSON, but it is passed to the assistant as a string exactly as typed. Use tool mocks to keep a run deterministic and to steer the conversation down a specific path without depending on a live service.

## Send webhooks on run start and end

Turn on webhooks to notify your server when a simulation run item starts or ends. On the **Tool mocks & webhooks** tab, under **Webhooks**, toggle **Simulation start** and **Simulation end**. Each fires a `POST` to your server URL.

<Warning>
  Webhooks fire for **voice simulations only**. They do not trigger in chat mode.
</Warning>

Vapi sends `simulation.run.started` when a run item goes live:

```json
{
  "type": "simulation.run.started",
  "simulationId": "8f2a9c1e-3b4d-4a7e-9c2f-1d6b0a5e7f34",
  "runId": "b7d4e2a0-6c9f-4e13-8a52-2f7c9b1d4e60",
  "simulationRunItemId": "c3e8f1a2-9d47-4b6c-8e30-5a1f2b9c7d84",
  "iterationNumber": 1,
  "isSimulation": true,
  "calls": {
    "testerCallId": "a1b2c3d4-...",
    "targetCallId": "e5f6a7b8-...",
    "listenUrl": "wss://..."
  },
  "timestamp": 1710000000000
}
```

Vapi sends `simulation.run.ended` when the run item finishes, adding the outcome:

```json
{
  "type": "simulation.run.ended",
  "simulationId": "8f2a9c1e-3b4d-4a7e-9c2f-1d6b0a5e7f34",
  "runId": "b7d4e2a0-6c9f-4e13-8a52-2f7c9b1d4e60",
  "simulationRunItemId": "c3e8f1a2-9d47-4b6c-8e30-5a1f2b9c7d84",
  "iterationNumber": 1,
  "isSimulation": true,
  "calls": { "testerCallId": "a1b2c3d4-...", "targetCallId": "e5f6a7b8-..." },
  "endedReason": "...",
  "canceled": false,
  "startedAt": "2026-07-28T17:10:05.000Z",
  "endedAt": "2026-07-28T17:12:30.000Z",
  "transcript": "...",
  "messages": [],
  "recordingUrl": "https://..."
}
```

Key fields: `calls.listenUrl` is a live-listen WebSocket URL for eavesdropping on the run; `iterationNumber` identifies which iteration of the run item this is; and the ended payload carries `endedReason`, `canceled`, `transcript`, `messages`, and `recordingUrl`. For the full list of `endedReason` values, see [Call ended reasons](/calls/call-ended-reason).

## Reuse structured outputs

Each evaluation references a [structured output](/assistants/structured-outputs). Reuse an existing structured output across simulations to keep the same criterion consistent, or create a new one inline from the **Evaluation plan** tab. For how structured outputs are defined, see the [structured outputs quickstart](/assistants/structured-outputs-quickstart).

## Set variable values for the target

Variables set values for the target assistant's [dynamic variables](/assistants/dynamic-variables) during the simulation. On the **Variables** tab, add `Name` / `Value` pairs: each name matches a `{{variable}}` placeholder in the target assistant's prompt, and the value is substituted in for the run.

Use variables to test the assistant with specific inputs — for example a customer name or account tier — without editing the assistant itself.
