Simulations are automated tests that run an AI tester through a real conversation with your assistant or squad and score the outcome. They matter because they catch broken flows, bad handoffs, and voice issues before a real caller does. This page explains what Simulations are and when to use them instead of Evals.

## Key concepts

| Term | Definition |
| -- | -- |
| Suite | A simulation suite is a group of simulations that run against the same target. |
| Simulation | A simulation pairs a scenario with a personality to test one situation. |
| Scenario | A scenario defines the tester's intent and the evaluations that judge the result. |
| Personality | A personality defines how the AI tester behaves, including its model, transcriber, and voice. |
| Tester | The tester is the AI caller that drives the conversation, configured by a personality. |
| Target | The target is the assistant or squad being tested. |
| Run | A run is one execution of a suite against its target. |
| Evaluation | An evaluation is a structured-output check that scores whether the conversation met a criterion. |

## How it works

A simulation recreates a real conversation instead of replaying a fixed script. The AI tester follows the scenario's intent, talks to your target over voice or chat, and the evaluations score whether the target behaved correctly.

You start from a suite. A suite names one or more targets, then holds the simulations you run against them. {/* [OK] suite-first entry point confirmed on preview */}

Each simulation combines a scenario and a personality. The scenario sets what the tester is trying to accomplish and the criteria for success. The personality sets who the tester is and how it speaks.

When you run the suite, each tester holds a live conversation with the target. {/* [PENDING] confirm run trigger + live-monitoring wording on staging */} Vapi then evaluates each conversation with structured outputs and reports a pass or fail for every simulation.

## Simulations vs Evals

Use Evals to test your agent's logic; use Simulations to test how it handles a real conversation. Both are testing tools in Vapi, and they complement each other.

Evals verify specific, expected behavior. You script a mock conversation — the user turns and the responses you expect — and assert the result with exact match, regex, an AI judge, or tool-call checks. Evals are deterministic and precise, which makes them a good fit for unit-style checks and CI/CD gates.

Simulations test the live interaction. An AI tester with a defined personality and intent improvises a real conversation with your assistant or squad, over voice or chat, and evaluations score the outcome with structured outputs. Simulations are dynamic, so they surface how your agent handles a realistic caller rather than a fixed script.

| | Evals | Simulations |
| -- | -- | -- |
| What you're testing | Your agent's framework and logic | How your agent handles a real conversation |
| What you provide | A scripted conversation with expected responses | A tester personality and an intent |
| How it runs | Deterministic, turn-by-turn assertions | Dynamic — the tester improvises the conversation |
| Transport | Chat (mock conversations) | Voice and chat |
| Evaluation | Exact match, regex, AI judge, tool-call checks | Structured outputs on the conversation outcome |
| Reach for it when | You need precise, repeatable checks or CI/CD gates | You need realistic end-to-end or voice behavior |

Choose Evals when you want to lock down a specific response, verify a tool call's arguments, or gate deploys with fast, repeatable checks.

Choose Simulations when you want to see how your agent performs against a realistic caller — different personalities, multi-turn flows, squad handoffs, or voice.
