## What versioning is

Versioning lets you save point-in-time snapshots of your configuration, publish them, and roll back to an earlier version. Assistants and tools are both versioned, and they work the same way. The lifecycle below is identical for each.

Use it to ship changes. Keep iterating without affecting live calls, publish when you're ready, and restore a previous version.

## The versioning lifecycle

The same lifecycle applies to assistants and tools:

- **Draft:** Your unpublished, in-progress edits. Drafts are private to you and don't affect live calls.
- **Publish:** Publishing a draft creates a new version, which becomes the **current** version in use.
- **History:** Every published version is kept, so you can see what changed and when.
- **Restore:** Roll back to an earlier version. Restoring publishes a new version that copies the older one and becomes current, and it doesn't edit or delete the history.

<Note>
"Current" is the version that's used as the latest or when you don't specify a version. Publishing or restoring is what changes which version is current.
</Note>

## Which version a call uses

- **Inbound calls** always use the assistant's **current** version, which is the latest one published. You cannot select a different version for inbound calls.
- **Outbound calls** use the current version by default. You can specify a different version to override it.
