## Overview

Versioning lets you save point-in-time snapshots of your configuration, publish them, and roll back to an earlier one if something goes wrong. **Both assistants and tools are versioned, and they work the same way** — the lifecycle below is identical for each.

Use it to ship changes confidently: keep iterating without affecting live calls, publish when you're ready, and restore a previous version if a change causes problems.

## The versioning lifecycle

The same lifecycle applies to assistants and tools:

- **Draft** — your unpublished, in-progress edits. Drafts are private to you and don't affect live calls.
- **Publish** — publishing a draft creates a new version, which becomes the **current** version (the one in use).
- **History** — every published version is kept, so you can see what changed and when.
- **Restore** — roll back to an earlier version. Restoring publishes a *new* version that copies the older one and becomes current; it doesn't edit or delete the history.

<Note>
"Current" is the version that's live. Publishing or restoring is what changes which version is current.
</Note>

## Versions and calls

- **Inbound calls** always use the assistant's **current** (latest published) version. You cannot select a different version for inbound calls.
- **Outbound calls** use the current version by default. You can specify a different version to override it.
