## Overview

Assistants follow the standard [versioning lifecycle](/assistants/versioning): you edit a draft, publish it to create a new version, and can restore an earlier one. Versions are immutable — you never edit a published version in place. To make changes, you edit a new draft and publish again, which creates the next version.

Open the version menu in the assistant header to see past versions, including who published each one and when. The current version is marked **Current**. {/* TODO(versioning): confirm history affordance + metadata fields */}

## Restore a previous version

You can roll back to any earlier version. Restoring publishes a **new** version that copies the older one and becomes current (for example, restoring `v6` creates a new `v8`); any unpublished draft changes are discarded.

When you restore an assistant version, the tool versions it used are restored too — except a tool set to **latest**, which always uses the newest version. See [How versioning works with assistants and tools](/assistants/versioning/versioning-with-assistants-and-tools).

## Which version a call uses

- **Inbound calls** always use the assistant's **current** (latest published) version. You cannot select a different version for inbound calls.
- **Outbound calls** use the current version by default. You can specify a different version to override it.
