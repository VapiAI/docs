## How assistant versioning works

Assistants follow the [versioning lifecycle](/assistants/versioning). You edit a draft, publish it to create a new version, and can restore an earlier one. Versions are immutable, so you never edit a published version in place. To make changes, edit a new draft and publish again, which creates the next version.

The assistant list and the assistant header show a **version badge** indicating which version you're currently on.

## Publish a new version

Publishing turns your current draft into a new version and makes it the **current** version.

<Steps>
  <Step title="Edit your draft">
    Make changes to the assistant. Your edits are saved automatically as a private draft and don't affect live calls.
  </Step>
  <Step title="Review the changes">
    Open **Publish** to see a diff of exactly what changed between the current version and your draft. In the diff view you can copy individual lines, wrap or unwrap long lines, and jump between the changes or copy the whole diff.
  </Step>
  <Step title="Name and describe the version">
    Give the version a name, and optionally a short description, so teammates can understand what changed and why.
  </Step>
  <Step title="Publish">
    Publish to create the new version and make it current. You can also **quick publish** using the current default settings, or **discard** your draft changes.
  </Step>
</Steps>

## View version history

Open the version dropdown in the assistant header to see recent versions, or open the **full history**. The current version is marked **Current**, and each version shows its version number, name, description, and when it was published.

From the full history you can:

- See the **diff** for a version
- **Download the JSON** of a version
- **Restore** a version with one click

## Restore a previous version

You can roll back to any earlier version. Restoring publishes a **new** version that copies the older one and becomes current. For example, restoring `v6` creates a new `v8`. Any unpublished draft changes are discarded.

When you restore an assistant version, the tool versions it used are restored too. The exception is a tool set to **latest**, which always uses the newest version. See [How versioning works with assistants and tools](/assistants/versioning/versioning-with-assistants-and-tools).

## Which version a call uses

- **Inbound calls** always use the assistant's **current** version, which is the latest one published. You cannot select a different version for inbound calls.
- **Outbound calls** use the current version by default.
