## Overview

Assistants and tools are versioned independently, but they come together when an assistant uses a tool. For each tool an assistant uses, you choose which tool version it runs — a specific version, or the latest. When you publish the assistant, those choices are recorded in that assistant version, so restoring the assistant later brings back the same tools.

## Choosing a tool version (Dashboard)

On the assistant's **Tools** tab, each tool has a version selector. Pick the version you want the assistant to use; it stays on that version until you change it. {/* TODO(versioning): confirm column/label names from design */}

## Using the latest version (API)

When you create an assistant or add a tool **via the API**, you can leave the tool's version unspecified. If you omit the version, the assistant uses the **latest** — the newest published version of that tool.

<Note>
This default exists to preserve **backwards compatibility**: no version specified = latest,
matching existing API behavior. Most customers create assistants and place outbound calls
through the API.

## How rollback affects tools

When you restore an assistant version, the tool versions it used are restored with it — except a tool set to `latest`, which always uses the newest version and is not rolled back.

Worked example:

- At **v6**, the assistant uses **Tool A v4** and **Tool B v6**.
- You restore the assistant to **v5**, which used **Tool A v2** and **Tool B v4**.
- After restoring, the assistant uses Tool A v2 and Tool B v4.
- If you had set Tool B to **latest** instead of a fixed version, it would keep using the newest published Tool B version after the restore — it would not roll back.
