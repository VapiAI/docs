## Overview

The **Vapi MCP Server** exposes Vapi APIs as tools via the Model Context Protocol (MCP), so you can manage assistants, phone numbers, and calls from any MCP-compatible AI assistant (like Claude) or agent framework.

Use this server to connect your AI workflows to real-world telephony, automate voice tasks, and build richer conversational agents.

<Note>
  Looking to use MCP tools *inside* a Vapi assistant? See the [MCP Tool documentation](/tools/mcp) for integrating *external* MCP servers with your Vapi agents.
</Note>

<Tip>
  Connect your coding agent directly to the hosted MCP server using its native MCP settings. The Vapi CLI is not required. For public agent skills and installation instructions, see [VapiAI/skills](https://github.com/VapiAI/skills).
</Tip>

<Note>
  If an earlier CLI release configured `@vapi-ai/mcp-docs-server` in your agent, replace that legacy entry with the hosted connection below. Existing agent configurations are not removed automatically.
</Note>

## Server URL and sign-in

The hosted server uses **Streamable HTTP** at:

```
https://mcp.vapi.ai/mcp
```

You sign in with your Vapi account over **OAuth**. There is no API key to copy:

<Steps>
  <Step title="Add the server">
    Add `https://mcp.vapi.ai/mcp` to your MCP client using the instructions for your client below.
  </Step>
  <Step title="Sign in">
    Your client opens a browser window. Sign in to Vapi the same way you sign in to the [dashboard](https://dashboard.vapi.ai): Google, GitHub, SSO, or email and password with MFA. If you're already signed in to the dashboard, this step is skipped.
  </Step>
  <Step title="Choose an organization">
    Pick the Vapi organization this connection can access and approve. Tools then act as you, in that organization, with your role's permissions.
  </Step>
</Steps>

Your client stores the session and refreshes it automatically, so you only sign in again if the session is revoked or you disconnect.

<Warning>
  The hosted server no longer accepts Vapi API keys. If your client configuration sends an `Authorization: Bearer` header with an API key, remove the header and sign in with OAuth instead.
</Warning>

## Connect your agent

<Tabs>
  <Tab title="Claude Code">
    Add the server to your user configuration:

    ```bash
    claude mcp add --transport http --scope user vapi https://mcp.vapi.ai/mcp
    ```

    Start a Claude Code session, run `/mcp`, select **vapi**, and choose **Authenticate**. Sign in and pick an organization in the browser.

    See [Claude Code MCP setup](https://code.claude.com/docs/en/mcp).
  </Tab>
  <Tab title="Claude">
    For Claude Desktop and claude.ai, add Vapi as a custom connector:

    1. Open **Settings → Connectors** and choose **Add custom connector**.
    2. Enter `Vapi` as the name and `https://mcp.vapi.ai/mcp` as the URL. Leave the advanced OAuth settings empty.
    3. Select **Connect**, then sign in and pick an organization in the browser.

    On Team and Enterprise plans, an owner adds the connector for the organization, and each member connects with their own Vapi account.

    See [Claude custom connectors](https://claude.com/docs/connectors/custom).
  </Tab>
  <Tab title="Codex">
    Register the server, then sign in:

    ```bash
    codex mcp add vapi --url https://mcp.vapi.ai/mcp
    codex mcp login vapi
    ```

    `codex mcp login` opens the browser to sign in and pick an organization. On a machine without a local browser, run `codex mcp login vapi --no-browser`, open the printed URL elsewhere, and paste the redirect URL back.

    See [Codex MCP setup](https://learn.chatgpt.com/docs/extend/mcp?surface=cli).
  </Tab>
  <Tab title="Cursor">
    Add this entry to `~/.cursor/mcp.json`, preserving any other servers:

    ```json
    {
      "mcpServers": {
        "vapi": {
          "url": "https://mcp.vapi.ai/mcp"
        }
      }
    }
    ```

    Open Cursor's MCP settings, enable `vapi`, and complete the sign-in when Cursor prompts you.

    See [Cursor MCP setup](https://cursor.com/docs/mcp).
  </Tab>
  <Tab title="VS Code">
    Run **MCP: Open User Configuration** from the Command Palette. Add this entry to `mcp.json`, preserving any other servers:

    ```json
    {
      "servers": {
        "vapi": {
          "type": "http",
          "url": "https://mcp.vapi.ai/mcp"
        }
      }
    }
    ```

    Start `vapi` from **MCP: List Servers** and sign in when VS Code asks you to authenticate.

    See [VS Code MCP setup](https://code.visualstudio.com/docs/agents/reference/mcp-configuration).
  </Tab>
  <Tab title="Hermes">
    Add the server to `~/.hermes/config.yaml`:

    ```yaml
    mcp_servers:
      vapi:
        url: "https://mcp.vapi.ai/mcp"
        auth: oauth
    ```

    Then sign in:

    ```bash
    hermes mcp login vapi
    ```

    Start a new session, or run `/reload-mcp` in an existing one. See [Hermes MCP setup](https://hermes-agent.nousresearch.com/docs/user-guide/features/mcp).
  </Tab>
  <Tab title="Other clients">
    Use Streamable HTTP at `https://mcp.vapi.ai/mcp` in any client that supports remote MCP servers with OAuth.

    If your client only supports local (stdio) servers, bridge to the hosted server with [`mcp-remote`](https://www.npmjs.com/package/mcp-remote), which handles the sign-in. This requires Node.js:

    ```json
    {
      "mcpServers": {
        "vapi": {
          "command": "npx",
          "args": ["-y", "mcp-remote", "https://mcp.vapi.ai/mcp"]
        }
      }
    }
    ```
  </Tab>
</Tabs>

Once connected, try asking your agent: "List my Vapi assistants."

## Core Tools

The Vapi MCP Server exposes these actions as MCP tools:

| Tool                   | Description                                      | Example Usage                                 |
|------------------------|--------------------------------------------------|-----------------------------------------------|
| `list_assistants`      | List all Vapi assistants                         | Show all configured assistants                |
| `create_assistant`     | Create a new Vapi assistant                      | Add a new assistant for a use case            |
| `get_assistant`        | Get a Vapi assistant by ID                       | View assistant config                         |
| `list_calls`           | List all calls                                   | Review call activity                          |
| `create_call`          | Create an outbound call (now or scheduled)       | Initiate or schedule a call                   |
| `get_call`             | Get details for a specific call                  | Check status or result of a call              |
| `list_phone_numbers`   | List all Vapi phone numbers                      | See available numbers                         |
| `get_phone_number`     | Get details of a specific phone number           | Inspect a phone number                        |
| `list_tools`           | List all available Vapi tools                    | Tool discovery                                |
| `get_tool`             | Get details of a specific tool                   | Tool integration info                         |

<Note>
  <b>Scheduling calls:</b> The <code>create_call</code> action supports scheduling with the optional <code>scheduledAt</code> parameter.
</Note>

## Custom MCP clients

If you're building your own MCP client, use an [MCP SDK](https://modelcontextprotocol.io/docs/sdk) that implements [MCP authorization](https://modelcontextprotocol.io/specification/latest/basic/authorization). The server follows the standard flow:

- An unauthenticated request gets `401` with a `WWW-Authenticate` header that points to the protected resource metadata at `https://mcp.vapi.ai/.well-known/oauth-protected-resource/mcp`.
- That metadata names the authorization server. Clients register with Dynamic Client Registration or a Client ID Metadata Document, then use the authorization code flow with PKCE.
- Request the scopes `openid offline_access` and the resource `https://mcp.vapi.ai/mcp`, then send the access token as `Authorization: Bearer <token>`.

## FAQ

<AccordionGroup>
  <Accordion title="Can I still use a Vapi API key with the hosted MCP server?">
    No. The hosted server only accepts OAuth sign-in. Remove any `Authorization` header or API key from your MCP configuration and follow the setup for your client above. API keys still work everywhere else in Vapi, including the [API](/api-reference) and [server SDKs](/sdks).
  </Accordion>

  <Accordion title="How do I use a different organization?">
    Each connection is bound to the organization you picked when you signed in. To switch, disconnect or clear the authentication in your client and sign in again. To use several organizations at once, add the server once per organization under different names, such as `vapi-prod` and `vapi-staging`.
  </Accordion>

  <Accordion title="What can the connection access?">
    The same things you can in the chosen organization, with your role's permissions. If you lose access to the organization, the connection stops working on the next request. The connection can't create or read API keys, credentials, or billing details.
  </Accordion>

  <Accordion title="How do I disconnect?">
    Remove the server from your client, or use its clear-authentication option (for example `/mcp` in Claude Code, or **Disconnect** for Claude connectors).
  </Accordion>

  <Accordion title="Can I use the MCP server in CI or other headless automation?">
    OAuth sign-in needs a person to approve it in a browser. For unattended jobs, call the [Vapi API](/api-reference) directly with an [API key](/security-and-privacy/api-keys), or use a [server SDK](/sdks).
  </Accordion>

  <Accordion title="What happened to the SSE endpoint?">
    The legacy HTTP+SSE endpoint (`https://mcp.vapi.ai/sse`) has been removed. Use Streamable HTTP at `https://mcp.vapi.ai/mcp`.
  </Accordion>

  <Accordion title="Sign-in fails or keeps asking me to authenticate">
    Clear the saved authentication for `vapi` in your client and connect again. Make sure you can sign in to the [dashboard](https://dashboard.vapi.ai) with the same account, and that you're a member of the organization you pick. If your company manages MCP connections centrally, ask your admin to allow `https://mcp.vapi.ai/mcp`.
  </Accordion>
</AccordionGroup>
