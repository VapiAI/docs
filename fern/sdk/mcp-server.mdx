## Overview

The **Vapi MCP server** gives AI agents Vapi tools over the Model Context Protocol (MCP). Once connected, your agent can search Vapi's documentation and manage your assistants, phone numbers, and calls.

Vapi hosts the server at `https://mcp.vapi.ai/mcp`, using the **Streamable HTTP** transport. You connect by signing in with your Vapi account: your agent opens a browser, you sign in and pick an organization, and the agent receives a short-lived token. No API key is involved, and you don't need the Vapi CLI. You can also [run the server locally](#run-the-server-locally).

<Note>
  Looking to use MCP tools *inside* a Vapi assistant? See [MCP tools](/tools/mcp).
</Note>

## Connect your agent

The hosted server uses OAuth, so there's nothing to copy and paste. Add the URL to your agent, then complete the sign-in in your browser.

<Tabs>
  <Tab title="Codex">
    Register the remote server, then sign in:

    ```bash
    codex mcp add vapi --url https://mcp.vapi.ai/mcp
    codex mcp login vapi
    ```

    Codex saves the connection in `~/.codex/config.toml` and registers itself with Vapi automatically. `codex mcp login` opens your browser; on a remote or headless machine, add `--no-browser` and paste the redirect URL back into the terminal.

    Start a new Codex session and use `/mcp` to inspect the connection. See [Codex MCP setup](https://developers.openai.com/codex/mcp).
  </Tab>
  <Tab title="Claude Code">
    Add the server to your private user configuration, then sign in:

    ```bash
    claude mcp add --transport http --scope user vapi https://mcp.vapi.ai/mcp
    claude mcp login vapi
    ```

    You can also sign in from inside a session: run `/mcp`, select `vapi`, and follow the browser prompts. The same menu has **Clear authentication** if you need to sign in again or switch organizations.

    See [Claude Code MCP setup](https://code.claude.com/docs/en/mcp).
  </Tab>
  <Tab title="Hermes">
    Add this entry to your active profile's `config.yaml`, preserving any other servers:

    ```yaml
    mcp_servers:
      vapi:
        url: "https://mcp.vapi.ai/mcp"
        auth: oauth
    ```

    Then sign in:

    ```bash
    hermes mcp login vapi
    ```

    Hermes handles registration and PKCE for you and stores the tokens under `~/.hermes/mcp-tokens/`. On a headless host, use `hermes mcp login vapi --flow device` to authorize with a code instead of a browser callback. Start a new session, or run `/reload-mcp` in an existing one, then:

    ```bash
    hermes mcp test vapi
    ```

    See [Hermes MCP setup](https://hermes-agent.nousresearch.com/docs/user-guide/features/mcp).
  </Tab>
  <Tab title="Cursor">
    Add this entry to your private user configuration at `~/.cursor/mcp.json`, preserving any other servers:

    ```json
    {
      "mcpServers": {
        "vapi": {
          "url": "https://mcp.vapi.ai/mcp"
        }
      }
    }
    ```

    No headers or keys are needed. Open Cursor's MCP settings, enable `vapi`, and complete the Vapi sign-in in your browser when Cursor prompts you. Then start a new chat.

    See [Cursor MCP setup](https://cursor.com/docs/mcp).
  </Tab>
  <Tab title="VS Code">
    Run **MCP: Open User Configuration** from the Command Palette. Add this entry to `mcp.json`, preserving any other servers:

    ```json
    {
      "servers": {
        "vapi": {
          "type": "http",
          "url": "https://mcp.vapi.ai/mcp"
        }
      }
    }
    ```

    Start `vapi` from **MCP: List Servers**. VS Code opens a browser window for the Vapi sign-in on the first connection. Then enable the server's tools in a chat session.

    See [VS Code MCP setup](https://code.visualstudio.com/docs/agents/reference/mcp-configuration).
  </Tab>
  <Tab title="Claude Desktop">
    Claude Desktop connects to remote servers as a custom connector, so no local bridge is needed.

    Open **Customize → Connectors**, click **+ Add**, then **Add custom connector**. Enter a name and `https://mcp.vapi.ai/mcp` as the remote MCP server URL, then click **Continue**. Leave the OAuth client option on **Register automatically**, finish with **Add**, then click **Connect** on the new connector and sign in to Vapi in your browser.

    On Team and Enterprise plans, an organization Owner adds the connector under **Organization settings → Connectors**.

    See [custom connectors via remote MCP](https://support.claude.com/en/articles/11175166-about-custom-connectors-via-remote-mcp).
  </Tab>
</Tabs>

Once connected, try asking your agent: "List my Vapi assistants."

## How signing in works

When your agent first connects, Vapi's server tells it where to sign in, and the agent opens that page in your browser. You sign in with your Vapi account — the same credentials, MFA, and SSO you use for the dashboard — and choose which organization the agent may act in. The agent then receives a short-lived access token and refreshes it as needed.

What this means day to day:

- **Your agent acts as you.** Every tool call runs with your own role and permissions in the organization you picked. A teammate connecting the same way sees only what their role allows.
- **One organization per connection.** To switch organizations, sign out and reconnect: `claude mcp logout vapi` then `claude mcp login vapi` in Claude Code, or the equivalent in your agent. Use the `get_connection_info` tool to check which user and organization the current connection is authorized as.
- **Some actions are always off-limits.** The hosted server can't read or create API keys, provider credentials, or billing settings, even if you're an admin.
- **Access follows your account.** Removing someone from your Vapi organization ends their agent's access; there's no separate key to find and rotate.

<Note>
  **Upgrading from API key authentication?** Before November 10, 2026, the hosted server accepted a Vapi API key in an `Authorization: Bearer` header, and also served the `https://mcp.vapi.ai/sse` endpoint. Both have been removed. Replace your existing `vapi` entry with the configuration for your agent above — delete the `headers` block or `--bearer-token-env-var` flag, keep the same `https://mcp.vapi.ai/mcp` URL, and sign in. If your agent uses `@vapi-ai/mcp-docs-server` from an earlier CLI release, replace that entry too; the hosted server includes documentation search. For documentation-only access with no sign-in at all, see [Search the docs without signing in](#search-the-docs-without-signing-in). Existing agent configurations are not changed automatically, and Vapi API keys continue to work for the [Vapi API](/api-reference) itself.
</Note>

## Run the server locally

You can run the open-source [Vapi MCP server](https://github.com/VapiAI/mcp-server) on your own machine instead of connecting to the hosted one, for example to develop against it. This requires Node.js. Your client starts the server as a subprocess and talks to it over stdio, so no HTTP endpoint is started.

The local server authenticates with a [Vapi API key](/security-and-privacy/api-keys) rather than sign-in, which also makes it the option for unattended automation. Because an API key carries full organization access, keep this configuration private.

Add this entry to your client's MCP configuration in place of the hosted connection. The local server reads your API key from `VAPI_TOKEN`:

```json
{
  "mcpServers": {
    "vapi": {
      "command": "npx",
      "args": ["-y", "@vapi-ai/mcp-server"],
      "env": {
        "VAPI_TOKEN": "YOUR_VAPI_API_KEY"
      }
    }
  }
}
```

In Claude Code, run:

```bash
claude mcp add -e VAPI_TOKEN=YOUR_VAPI_API_KEY vapi -- npx -y @vapi-ai/mcp-server
```

## Search the docs without signing in

For documentation search alone, connect your agent to Vapi's documentation MCP server at `https://docs.vapi.ai/_mcp/server`. It needs no account and provides a `searchDocs` tool. The Vapi MCP server's `ask_vapi_docs` tool runs the same search.

If your client can't connect to a remote server directly, run it through the `mcp-remote` adapter:

```json
{
  "mcpServers": {
    "vapi-docs": {
      "command": "npx",
      "args": ["-y", "mcp-remote", "https://docs.vapi.ai/_mcp/server"]
    }
  }
}
```

## Available tools

The Vapi MCP server exposes the tools below. The hosted server and the [local server](#run-the-server-locally) expose the same set, except for `get_connection_info`, which only the hosted server provides.

### Connection

| Tool                  | Description                                                                         |
|-----------------------|-------------------------------------------------------------------------------------|
| `get_connection_info` | Show the Vapi user, organization, and OAuth client this connection is authorized as  |

### Documentation and reference

| Tool             | Description                                                                 |
|------------------|-----------------------------------------------------------------------------|
| `ask_vapi_docs`  | Search Vapi documentation and return relevant passages with source URLs      |
| `get_api_schema` | Look up a schema in the Vapi API reference, the OpenAPI spec the SDKs are generated from |
| `search_skills`  | Find Vapi agent skills in the public `VapiAI/skills` repository              |
| `load_skill`     | Read a public Vapi skill or one of its supporting files                      |

The `load_skill` tool returns instructions for the agent to follow. It does not install skills or run scripts.

### Assistants

| Tool               | Description                        |
|--------------------|------------------------------------|
| `list_assistants`  | List all Vapi assistants           |
| `get_assistant`    | Get a Vapi assistant by ID         |
| `create_assistant` | Create a new Vapi assistant        |
| `update_assistant` | Update an existing Vapi assistant  |

### Calls

| Tool          | Description                        |
|---------------|------------------------------------|
| `list_calls`  | List all calls                     |
| `get_call`    | Get details for a specific call    |
| `create_call` | Create an outbound call, now or scheduled |

To schedule a call, pass the optional `scheduledAt` parameter to `create_call`.

<Info>
  The `create_call` tool places a real phone call.
</Info>

### Phone numbers

| Tool                 | Description                            |
|----------------------|----------------------------------------|
| `list_phone_numbers` | List all Vapi phone numbers            |
| `get_phone_number`   | Get details of a specific phone number |

### Vapi tools

| Tool          | Description                       |
|---------------|-----------------------------------|
| `list_tools`  | List all Vapi tools               |
| `get_tool`    | Get details of a specific tool    |
| `create_tool` | Create a new Vapi tool            |
| `update_tool` | Update an existing Vapi tool      |

### Simulations

These tools drive [simulations](/observability/simulations-overview), which test an assistant against an AI tester.

| Tool                             | Description                                                                 |
|----------------------------------|-----------------------------------------------------------------------------|
| `list_simulation_personalities`  | List simulation personalities, which set how the AI tester behaves           |
| `create_simulation_personality`  | Create a personality that sets how the AI tester behaves                     |
| `list_simulation_scenarios`      | List simulation scenarios, the AI tester's intent and the checks that decide pass or fail |
| `create_simulation_scenario`     | Create a scenario: AI tester instructions plus the evaluations that decide pass or fail |
| `list_simulations`               | List simulations, each pairing one scenario with one personality             |
| `create_simulation`              | Create a simulation that pairs a scenario with a personality                 |
| `list_simulation_suites`         | List simulation suites, which are named groups of simulations                |
| `create_simulation_suite`        | Create a suite that groups simulations so they can be run together           |
| `run_simulations`                | Start a run of simulations or suites against an assistant or squad           |
| `list_simulation_runs`           | List simulation runs, newest first                                           |
| `get_simulation_run`             | Get a run with its status, item counts, and item summaries                   |
| `get_simulation_run_item`        | Get one run item in full, including results, call snapshots, and transcript   |

<Info>
  Each `run_simulations` tool call starts a billed simulation run. For more information, see [Simulations overview](/observability/simulations-overview).
</Info>

Which tools succeed depends on your role in the organization you signed in to. A call that your role doesn't permit fails with an authorization error.

## Use the server from your own code

Any MCP client can connect to `https://mcp.vapi.ai/mcp` over Streamable HTTP, but it has to complete the same browser sign-in; the server rejects Vapi API keys. Requests without a valid token are answered with `401` and a `WWW-Authenticate` challenge pointing at the server's metadata at `https://mcp.vapi.ai/.well-known/oauth-protected-resource/mcp`, which is how clients discover where to sign in.

<Note>
  Signing in requires a person at a browser, and the resulting tokens are short-lived. For unattended server-to-server automation, call the [Vapi API](/api-reference) directly with an API key, or [run the server locally](#run-the-server-locally) with `VAPI_TOKEN`.
</Note>

The simplest option is the `mcp-remote` adapter, which performs the sign-in once, caches the tokens under `~/.mcp-auth`, and exposes the server over stdio:

```bash
npx -y mcp-remote https://mcp.vapi.ai/mcp
```

### Hosted agent platforms

Platforms that call remote MCP servers on your behalf, such as the [OpenAI Responses API](https://developers.openai.com/api/docs/guides/tools-connectors-mcp), can use the hosted server. Pass an access token from the sign-in flow in the `authorization` field, not a Vapi API key:

<CodeBlocks>
```typescript title="typescript"
import OpenAI from 'openai';

const openai = new OpenAI({ apiKey: process.env.OPENAI_API_KEY });

const response = await openai.responses.create({
  model: 'gpt-4.1',
  tools: [
    {
      type: 'mcp',
      server_label: 'vapi',
      server_url: 'https://mcp.vapi.ai/mcp',
      authorization: process.env.VAPI_MCP_ACCESS_TOKEN,
    },
  ],
  input: 'List my Vapi assistants.',
});

console.dir(response, { depth: null });
```
```python title="python"
import os
from openai import OpenAI

client = OpenAI(api_key=os.environ["OPENAI_API_KEY"])

response = client.responses.create(
    model="gpt-4.1",
    tools=[
        {
            "type": "mcp",
            "server_label": "vapi",
            "server_url": "https://mcp.vapi.ai/mcp",
            "authorization": os.environ["VAPI_MCP_ACCESS_TOKEN"],
        },
    ],
    input="List my Vapi assistants.",
)

print(response)
```
</CodeBlocks>

The token is short-lived and the platform does not store it, so send a current one with every request. The Responses API also asks for your approval before calling a remote server unless you set `require_approval`.

### MCP client SDKs

Official MCP SDKs are available for [TypeScript](https://github.com/modelcontextprotocol/typescript-sdk), [Python](https://github.com/modelcontextprotocol/python-sdk), [Java](https://github.com/modelcontextprotocol/java-sdk), [Kotlin](https://github.com/modelcontextprotocol/kotlin-sdk), and [C#](https://github.com/modelcontextprotocol/csharp-sdk). They include OAuth helpers that run the sign-in and refresh tokens for you; see the [MCP authorization spec](https://modelcontextprotocol.io/specification/basic/authorization) for how the flow works.

If you already hold a valid access token, pass it to the transport. This minimal Node.js client lists your assistants:

```javascript
import { Client } from '@modelcontextprotocol/sdk/client/index.js';
import { StreamableHTTPClientTransport } from '@modelcontextprotocol/sdk/client/streamableHttp.js';
import dotenv from 'dotenv';

dotenv.config();

const mcpClient = new Client({ name: 'vapi-client', version: '1.0.0' });
const transport = new StreamableHTTPClientTransport(
  new URL('https://mcp.vapi.ai/mcp'),
  { requestInit: { headers: { Authorization: `Bearer ${process.env.VAPI_MCP_ACCESS_TOKEN}` } } }
);

async function main() {
  await mcpClient.connect(transport);
  const assistants = await mcpClient.callTool({ name: 'list_assistants', arguments: {} });
  console.log(assistants);
  await mcpClient.close();
}

main();
```

`VAPI_MCP_ACCESS_TOKEN` is an access token from the sign-in flow, not a Vapi API key. It expires, so production clients should use an SDK OAuth provider that refreshes it instead of a token pasted into the environment.

This fuller example lists tools, assistants, and phone numbers, then creates a call:

```javascript
#!/usr/bin/env node
import { Client } from '@modelcontextprotocol/sdk/client/index.js';
import { StreamableHTTPClientTransport } from '@modelcontextprotocol/sdk/client/streamableHttp.js';
import dotenv from 'dotenv';

// Load environment variables from .env file
dotenv.config();

// Ensure an access token from the sign-in flow is available
if (!process.env.VAPI_MCP_ACCESS_TOKEN) {
  console.error('Error: VAPI_MCP_ACCESS_TOKEN environment variable is required');
  process.exit(1);
}

async function main() {
  try {
    // Initialize MCP client
    const mcpClient = new Client({
      name: 'vapi-client-example',
      version: '1.0.0',
    });
    // Create Streamable HTTP transport for connection to remote Vapi MCP server
    const serverUrl = 'https://mcp.vapi.ai/mcp';
    const headers = {
      Authorization: `Bearer ${process.env.VAPI_MCP_ACCESS_TOKEN}`,
    };
    const options = {
      requestInit: { headers: headers },
    };
    const transport = new StreamableHTTPClientTransport(new URL(serverUrl), options);
    console.log('Connecting to Vapi MCP server via Streamable HTTP...');
    await mcpClient.connect(transport);
    console.log('Connected successfully');

    // Helper function to parse tool responses
    function parseToolResponse(response) {
      if (!response?.content) return response;
      const textItem = response.content.find(item => item.type === 'text');
      if (textItem?.text) {
        try {
          return JSON.parse(textItem.text);
        } catch {
          return textItem.text;
        }
      }
      return response;
    }

    try {
      // List available tools
      const toolsResult = await mcpClient.listTools();
      console.log('Available tools:');
      toolsResult.tools.forEach((tool) => {
        console.log(`- ${tool.name}: ${tool.description}`);
      });

      // List assistants
      console.log('\nListing assistants...');
      const assistantsResponse = await mcpClient.callTool({
        name: 'list_assistants',
        arguments: {},
      });
      const assistants = parseToolResponse(assistantsResponse);
      if (!(Array.isArray(assistants) && assistants.length > 0)) {
        console.log('No assistants found. Please create an assistant in the Vapi dashboard first.');
        return;
      }
      console.log('Your assistants:');
      assistants.forEach((assistant) => {
        console.log(`- ${assistant.name} (${assistant.id})`);
      });

      // List phone numbers
      console.log('\nListing phone numbers...');
      const phoneNumbersResponse = await mcpClient.callTool({
        name: 'list_phone_numbers',
        arguments: {},
      });
      const phoneNumbers = parseToolResponse(phoneNumbersResponse);
      if (!(Array.isArray(phoneNumbers) && phoneNumbers.length > 0)) {
        console.log('No phone numbers found. Please add a phone number in the Vapi dashboard first.');
        return;
      }
      console.log('Your phone numbers:');
      phoneNumbers.forEach((phoneNumber) => {
        console.log(`- ${phoneNumber.phoneNumber} (${phoneNumber.id})`);
      });

      // Create a call using the first assistant and first phone number.
      // Outbound calls need an imported number. With free Vapi numbers, only inbound calls are supported.
      const phoneNumberId = phoneNumbers[0].id;
      const assistantId = assistants[0].id;
      console.log(`\nCreating a call using assistant (${assistantId}) and phone number (${phoneNumberId})...`);
      const createCallResponse = await mcpClient.callTool({
        name: 'create_call',
        arguments: {
          assistantId: assistantId,
          phoneNumberId: phoneNumberId,
          customer: {
            number: "+1234567890"  // Replace with actual customer phone number
          }
          // Optional: schedule a call for the future
          // scheduledAt: "2025-04-15T15:30:00Z"
          // assistantOverrides: {
          //  variableValues: {
          //   name: 'John Doe',
          //   age: '25',
          //  },
          // },
        },
      });
      const createdCall = parseToolResponse(createCallResponse);
      console.log('Call created:', JSON.stringify(createdCall, null, 2));
    } finally {
      console.log('\nDisconnecting from server...');
      await mcpClient.close();
      console.log('Disconnected');
    }
  } catch (error) {
    console.error('Error:', error);
    process.exit(1);
  }
}

main();
```
