<Warning>
Sign tokens only on your server. Never send your private API key to a browser, a mobile app, or any other client.
</Warning>

A Vapi JSON Web Token (JWT) is a short-lived credential that you sign on your server with your private API key. Vapi doesn't issue these tokens. Your server creates them, and Vapi checks the signature on each request.

Use a public JWT in the Vapi Web SDK in place of a public API key. Each token expires within 1 hour and can carry its own origin and assistant restrictions.

## How it works

Your server signs a JWT with the HS256 algorithm, using your private API key as the secret. Your client sends the token in the `Authorization` header, or passes it to the [Vapi Web SDK](/quickstart/web). Vapi verifies the signature against each private API key in the organization named by the token's `orgId` claim.

The `token.tag` claim sets what the token can be used for:

| `token.tag` | Works with | Use it for |
| --- | --- | --- |
| `"public"` | Starting calls with the [Vapi Web SDK](/quickstart/web) | Browser apps |
| `"private"` | All other API requests | Short-lived server-to-server access |

A public JWT works only with the Web SDK, and a private JWT can't start Web SDK calls. If you leave out the `token` claim, the JWT is treated as public.

## Prerequisites

- A private API key and your [organization ID](/security-and-privacy/api-keys#find-your-organization-id)
- A server that runs Node.js 18 or later, where you can store the private API key as a secret
- An assistant to use in Web SDK calls

## Signing requirements

Every Vapi JWT must meet these requirements:

| Requirement | Value |
| --- | --- |
| Algorithm | `HS256`. Other algorithms, including `HS384`, `HS512`, and `none`, are rejected. |
| Signing secret | Your private API key, exactly as you copied it from the Dashboard. Don't Base64-decode or hex-decode it, and don't generate a separate key pair. A public API key can't sign tokens. |
| `exp` claim | Required. A Unix timestamp in seconds, no more than 1 hour after the time of the request. |
| `nbf` claim | Optional. If set, the token is rejected until this Unix timestamp in seconds. |
| `orgId` claim | Required. Your organization ID, a UUID. |
| `token` claim | Optional object with the token's tag and restrictions. Unknown fields inside it are rejected. |

Don't set the `iss` claim to `https://api.vapi.ai`. That issuer is reserved for tokens Vapi creates, and your token fails verification. Other top-level claims are ignored.

### Token claim fields

The `token` claim accepts these fields:

| Field | Type | Description |
| --- | --- | --- |
| `tag` | `"public"` or `"private"` | What the token can be used for. Defaults to `"public"` when `token` is left out. |
| `name` | string | Optional label for your own reference. |
| `restrictions` | object | Limits for a public token. For more information, see [Restrict a public token](#restrict-a-public-token). |

## Create a public token

<Steps>
  <Step title="Install a JWT library">
    Install [`jsonwebtoken`](https://www.npmjs.com/package/jsonwebtoken) in your server project:

    ```bash
    npm install jsonwebtoken
    ```
  </Step>

  <Step title="Store your credentials on the server">
    Set your private API key and organization ID as environment variables on your server:

    ```bash
    export VAPI_PRIVATE_API_KEY="YOUR_PRIVATE_API_KEY"
    export VAPI_ORG_ID="YOUR_ORG_ID"
    ```
  </Step>

  <Step title="Sign the token">
    Save this script as `create-public-token.mjs`, replace the example origin and assistant ID with your own, then run `node create-public-token.mjs`:

    ```javascript title="JavaScript (Node.js): create-public-token.mjs"
    import jwt from "jsonwebtoken";

    const payload = {
      orgId: process.env.VAPI_ORG_ID,
      token: {
        tag: "public",
        restrictions: {
          allowedOrigins: ["https://app.example.com"],
          allowedAssistantIds: ["00000000-0000-4000-8000-000000000001"],
        },
      },
    };

    const token = jwt.sign(payload, process.env.VAPI_PRIVATE_API_KEY, {
      algorithm: "HS256",
      expiresIn: "1h",
    });

    console.log(token);
    ```

    In a real app, create the token in a server endpoint that your client calls, and return the token in the response.
  </Step>

  <Step title="Start a web call with the token">
    If you haven't installed the Web SDK in your client project, run `npm install @vapi-ai/web`.

    Pass the token to the Vapi Web SDK in place of a public API key:

    ```javascript title="JavaScript (Web SDK)"
    import Vapi from "@vapi-ai/web";

    const vapi = new Vapi("YOUR_JWT");
    vapi.start("00000000-0000-4000-8000-000000000001");
    ```

    Before each new call, request a fresh token from your server and create a new `Vapi` instance with it. The SDK keeps the token it received when constructed, so an existing instance will continue using an expired token.
  </Step>
</Steps>

## Restrict a public token

Restrictions limit where a public token works and which assistants it can use. Set them in `token.restrictions`. Restrictions apply only to public tokens, and a request that breaks one fails with a `403` response.

| Field | Type | Effect |
| --- | --- | --- |
| `allowedOrigins` | string[] | The request's `Origin` header must match one of these origins. A request with no `Origin` header is rejected. |
| `allowedAssistantIds` | string[] | The request's `assistantId` must be in this list. Requests for squads and transient assistants are rejected. If you set this field, include at least one ID. |
| `allowTransientAssistant` | boolean | Set to `false` to reject [transient assistants](/assistants/concepts/transient-vs-permanent-configurations). This field has no effect when `allowedAssistantIds` is set. |
| `enabled` | boolean | Set to `false` to reject every request that uses the token. Restrictions apply whether or not you set this field. |

Allowed origins follow these rules:

- Enter each origin as a scheme, host, and optional port. Any path is ignored.
- Match the scheme, host, and port to the `Origin` header the browser sends.
- Use `*` in place of one whole subdomain label. For example, `https://*.example.com` matches `https://app.example.com` but not `https://example.com` or `https://a.b.example.com`.
- Don't use partial wildcards, such as `https://myapp-*.example.com`. They never match.

## Create a private token

A private JWT works with the same endpoints as a private API key. Use it to give another service short-lived API access without sharing your private API key.

Sign it the same way as a public token, with `tag` set to `"private"`. Save this script as `create-private-token.mjs`, then run `node create-private-token.mjs`:

```javascript title="JavaScript (Node.js): create-private-token.mjs"
import jwt from "jsonwebtoken";

const payload = {
  orgId: process.env.VAPI_ORG_ID,
  token: {
    tag: "private",
  },
};

const token = jwt.sign(payload, process.env.VAPI_PRIVATE_API_KEY, {
  algorithm: "HS256",
  expiresIn: "1h",
});

console.log(token);
```

Send the token in the `Authorization` header as a bearer token, the same way you send a private API key.

## Verify it works

To check a private token, sign one and use it to list your assistants. Save this script as `verify-private-token.mjs`, then run `node verify-private-token.mjs`:

```javascript title="JavaScript (Node.js): verify-private-token.mjs"
import jwt from "jsonwebtoken";

const payload = {
  orgId: process.env.VAPI_ORG_ID,
  token: {
    tag: "private",
  },
};

const token = jwt.sign(payload, process.env.VAPI_PRIVATE_API_KEY, {
  algorithm: "HS256",
  expiresIn: "1h",
});

const response = await fetch("https://api.vapi.ai/assistant", {
  headers: { Authorization: `Bearer ${token}` },
});

console.log(response.status);
console.log(await response.json());
```

A `200` status and a JSON list of your assistants confirm that your server signs tokens correctly.

<Note>
If your organization has no assistants, a `200` response with an empty list (`[]`) still confirms that Vapi accepted the token.
</Note>

To check a public token, start a web call from one of its allowed origins. The call starts if the token is valid. If the request fails with a `401` or `403` response, see [Troubleshoot token errors](#troubleshoot-token-errors).

## Troubleshoot token errors

A `401` response means the token failed verification. A `403` response means a public token's restrictions rejected the request.

### 401 Unauthorized: token errors

| Error message | Cause | Fix |
| --- | --- | --- |
| `Couldn't verify JWT.` | The token wasn't signed with HS256 and one of the organization's private API keys. | Sign with `algorithm: "HS256"` and the private API key string, unchanged. |
| `No Private Key Found.` | The `orgId` claim doesn't match an organization with a private API key. | Set `orgId` to the organization that owns the signing key. |
| `JWT is missing exp claim.` | The token has no expiration. | Set `exp`, for example with `expiresIn: "1h"`. |
| `JWT has expired.` | The `exp` time has passed. | Request a new token. |
| `JWT can't have expiration more than an hour into the future.` | `exp` is more than 1 hour away, or is in milliseconds. | Set `exp` no more than 1 hour ahead, in seconds. |
| `Invalid exp claim in JWT. Expected seconds since UNIX epoch.` | `exp` isn't a number. | Set `exp` to a Unix timestamp in seconds. |
| `JWT is not yet valid.` | The `nbf` time is in the future. | Remove `nbf` or set it to the current time or earlier. |
| `JWT is missing orgId.` or `Invalid orgId. Expected a UUID.` | The `orgId` claim is missing or isn't a UUID. | Set `orgId` to your organization ID. |
| `Invalid JWT. token.tag must be one of the following values: private, public` | `token.tag` has another value. | Set `tag` to `"public"` or `"private"`. |
| `Invalid JWT. token.property <field> should not exist` | The `token` claim has an unsupported field. | Use only the fields in [Token claim fields](#token-claim-fields) and [Restrict a public token](#restrict-a-public-token). |
| `Invalid JWT. token.restrictions.allowedAssistantIds should not be empty` | `allowedAssistantIds` is an empty list. | Add at least one assistant ID, or remove the field. |
| `Invalid JWT. Invalid aud claim.` | The `iss` claim is set to `https://api.vapi.ai`. | Remove `iss` or set it to your own issuer. |
| ``JWT doesn't permit access. Hot tip, you may be setting the wrong `token.tag`.`` | The token's `tag` doesn't match the endpoint. | Use `"public"` for the Web SDK and `"private"` for other API requests. |
| ``JWT doesn't permit access. Hot tip, you may be missing `token` in your JWT.`` | The token has no `token` claim, so it's treated as public. The endpoint requires `"private"`. | Add `token: { tag: "private" }`. |

### 403 Forbidden: restriction errors

| Error message | Cause | Fix |
| --- | --- | --- |
| `Key doesn't allow origin '...'.` | The `Origin` header is missing or isn't in `allowedOrigins`. | Add the origin to `allowedOrigins`, matching its scheme, host, and port. |
| `Key doesn't allow assistantId '...'.` | The assistant isn't in `allowedAssistantIds`, or the request uses a squad. | Add the assistant ID, or remove `allowedAssistantIds`. |
| `Key doesn't allow transient assistant.` | The request includes an `assistant` object. | Use a saved assistant's ID, or set `allowTransientAssistant` to `true`. |
| `Key is disabled.` | The token sets `restrictions.enabled` to `false`. | Remove `enabled` or set it to `true`. |
