Connect a Telnyx number to your agent by pasting a Telnyx API key into [Vapi for CX](https://cx.vapi.ai) and picking your numbers.

- **Receive calls:** Yes.
- **Transfer to a phone number:** Yes, once the Vapi application is on an Outbound Voice Profile. Whoever answers sees the agent's number.
- **Transfer to a SIP address:** Yes, with named caller details and no summary.
- **Return the call to their system:** No.
- **Place calls:** Yes, once the Vapi application is on an Outbound Voice Profile. The caller ID must be valid for the account.

## Send calls to the agent

<Steps>
  <Step title="Create a v2 API key">
    In the Telnyx portal, open [API Keys](https://portal.telnyx.com/#/app/api-keys) and create a v2 API key. Keys are account-wide. For more information, see Telnyx's [authentication](https://developers.telnyx.com/docs/development/api-fundamentals/authentication) page.
  </Step>
  <Step title="Paste it into Vapi for CX">
    On the agent's setup checklist, open **Connect your phone line**, choose **Another carrier or my own phone system**, then **Telnyx**. Paste the key and choose **Find my numbers**. Vapi keeps the key and never shows it again. Vapi for CX doesn't keep it.
  </Step>
  <Step title="Pick your numbers">
    Vapi for CX lists each number and the connection it is on today. Tick the numbers this agent answers and choose **Connect**. Vapi for CX saves each number's old connection so that **Disconnect** can put it back.

    A Telnyx number has one connection. Connecting it to the agent stops its calls going to its old SIP connection, TeXML app or Voice API app at once, so your phone system stops receiving them. Vapi for CX warns you before you confirm. A number outside North America shows a warning too: on this route its calls can sound garbled, and the trunk route avoids that.

    Vapi creates an application named "Vapi" in your Telnyx account (in the Telnyx portal under **Voice › Programmable Voice**) and moves each number onto it. Nothing else on the number changes. For more information, see [Vapi's Telnyx guide](/telnyx).
  </Step>
</Steps>

**Number the agent sees:** the caller's own number. Telnyx sends only the caller's number and the dialed number.

**Check it:** when Vapi for CX shows **Call this number from your phone**, call the number from your own phone. The check passes when the agent answers. Handoffs and calls out need the Outbound Voice Profile below.

**Disconnect.** Disconnecting a Telnyx number never deletes it. Vapi for CX asks you to paste the API key again, moves the number back onto its old connection, then detaches the agent. The number stays in Vapi. If that fails, the agent stays attached and the message says what to set in the Telnyx portal.

## Hand callers to your team

On a line connected by key, no summary travels with a handoff. For how handoffs work, see [Handing callers to people](/phone-systems#handing-callers-to-people).

### Transfer to a phone number

Vapi asks Telnyx to transfer the call, and Telnyx dials the number.

<Steps>
  <Step title="Add the Vapi application to an Outbound Voice Profile">
    In the Telnyx portal, open **Voice › [Outbound Voice Profiles](https://portal.telnyx.com/#/outbound-profiles)**. Create or open a profile and choose its destinations (the default is the US and Canada; many others need Telnyx's Level 2 verification). Use **Add connections/apps to profile**, pick **Vapi**, and save. For more information, see Telnyx's [outbound voice profiles](https://developers.telnyx.com/docs/voice/sip-trunking/configuration/outbound-voice-profiles) page.

    Vapi for CX reminds you of this step when you add a handoff on a Telnyx line. The same profile lets the agent place calls.
  </Step>
  <Step title="Add the handoff">
    On the agent's **Call handling** tab, choose **Add a handoff** on the **Handing callers to people** card and pick **Transfer to a phone number**. Say when the agent should hand off, and enter the number.
  </Step>
</Steps>

**Number whoever answers sees:** the agent's own Telnyx number, not the caller's. Telnyx sets it and ignores the agent's caller ID setting.

### Transfer to a SIP address

Telnyx transfers the call to the SIP address. Named caller details travel with it as `X-` headers. The Outbound Voice Profile above applies here too.

## Limitations

- On a line connected by key, no summary travels with a handoff, and whoever answers sees the agent's number. If nobody answers, the call ends: it doesn't come back to the agent.
- Telnyx has no call flow to take the caller back, so **Return the call to their system** isn't available.
- Vapi for CX connects one Telnyx account per organization. A second account uses the trunk route.
- Audio is G.711 µ-law only on this route, so numbers outside North America can sound garbled. Use the trunk route for them.
- Telnyx bills the call at its Voice API and media-streaming rates, and a handoff adds a second Telnyx leg for the rest of the call. Vapi bills its own minutes. A trial account can only call its one verified number.
- Vapi doesn't port numbers.

## Other options

<Accordion title="Other ways to connect Telnyx">
- **SIP trunk (Connect in Vapi).** For a summary with each SIP handoff, numbers outside North America, or a second Telnyx account. This page gives no steps for it. It takes a SIP connection in the Telnyx portal, set up as [Vapi's Telnyx SIP guide](/advanced/sip/telnyx) describes, and one SIP trunk in Vapi's dashboard that holds both Telnyx's addresses for calls in (`192.76.120.10` and `64.16.250.10`) and the sign-in for calls out, with **Leading Plus for Outbound** turned on in its **Advanced Settings**. In the Telnyx portal, each number's **Translated Number** names a Vapi SIP address, and Telnyx sends the number's calls to that address, so this setup makes two Vapi numbers for one line. On a trunk line, a SIP handoff passes the call on, keeps the caller's number, and carries the summary and named details.
- **Forward the Telnyx number to a Vapi number.** Call forwarding on the number in Telnyx. It costs a second Telnyx leg, so it is a fallback, not a main route.
- **Telnyx AI Assistants or media streaming:** nothing to connect. Connecting by key already uses media streaming.
</Accordion>
