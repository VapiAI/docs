These pages explain how to connect a phone line to an agent in [Vapi for CX](https://cx.vapi.ai) and how the agent hands callers to your people. There is one page for each carrier, phone system and contact center. Each page covers both directions: how a caller reaches the agent, and how the agent passes the caller back to a person or to your own system.

The steps were read from the vendor's own documentation and from Vapi's code on Nov 22, 2026. Where a step was not read on the vendor's own page, or could not be confirmed, the page says so beside it. Nothing on these pages has been proven with a real call yet.

## Vapi for CX and Vapi's dashboard

Vapi for CX is the app at [cx.vapi.ai](https://cx.vapi.ai), where you build and run agents. Vapi's dashboard is Vapi's own console, at [dashboard.vapi.ai](https://dashboard.vapi.ai). Both use the same login, and a phone number set up in one shows in the other.

You connect a phone line from the agent's setup checklist, in the step **Connect your phone line**. Every agent starts with a free starter number from Vapi. **Keep the starter** finishes the step with that number.

## How each integration connects

At the top of every page, one of these four labels says what Vapi for CX offers for that integration at launch:

- **Connect in the app.** Vapi for CX connects the line itself: Twilio, Telnyx and Vonage numbers by key, a business line forwarded to the agent, and a SIP address for the agent.
- **Connect in Vapi, then pick the number.** Vapi for CX has no form for this carrier. You set the number up in Vapi's dashboard (**Connect in Vapi**), then pick it in Vapi for CX with **Use a number already in Vapi**.
- **Vapi for CX's contact-center screen, then this page.** You forward calls from the phone system or contact center to the agent's number. One screen in Vapi for CX covers every platform, and links to the platform's page here for the steps on their side.
- **Coming soon.** The route waits on the vendor's approval or on steps nobody has walked yet. It is not available at launch. <a href="https://vapi.ai/sales" target="_blank" rel="noopener">Contact sales</a> to ask about it.

After any line is connected, Vapi for CX asks you to **Call this number from your phone**. The line is marked as working when that first call reaches the agent.

## What the verdicts mean

Each page opens with an "At a glance" table that gives four verdicts: receiving calls, transferring out, calls out, and self-serve.

- **Works today:** the vendor's documentation and Vapi's code say it works with nothing new built.
- **Works with a caveat:** it works, with a limit or an untested piece that the page names.
- **Can't:** the vendor does not allow it, or there is no way to do it.
- **Coming soon:** not available at launch; <a href="https://vapi.ai/sales" target="_blank" rel="noopener">Contact sales</a> to ask about it.
- **Doesn't apply:** the step has no meaning for this integration.

Beside a step you may see one of these notes:

- **Not run:** read from documentation or code, never tried with a real call.
- **Needs a test call:** it should work, and one real call will prove it.
- **Yes, on paper:** the documentation says yes; no call has confirmed it.
- **Not verified: not read on the vendor's own page:** the vendor's own documentation does not say this, or could not be read.

## Handing callers to people

Handoffs are set on the agent, on the **Handing callers to people** card on the Call handling tab. There are three types:

- **Transfer to a phone number:** the agent passes the caller to a number of yours, such as a queue, a team or a person. It works on every line except a phone system that sends audio over WebSocket.
- **Transfer to a SIP address:** the agent passes the caller to an address on your phone system. Where the line allows it, a summary and named details travel with the call.
- **Return the call to their system:** the agent says its last words and ends its part of the call, and your phone system or contact center carries on with the caller. It is offered only when a phone system or contact center that takes calls back is linked to the agent's line. Nothing tells your system why the agent handed the caller back, so the caller goes to your flow's default path.

Which types a line allows depends on the line the call arrives on. Each page says which apply.

## The three groups

- **Carriers** sell phone numbers and calls. Their numbers connect to the agent directly, either in Vapi for CX or in Vapi's dashboard.
- **Phone systems** are your business's own phone setup, such as an office phone system or a phone company's line, that forwards calls to the agent.
- **Contact centers** route calls to the agent from their own call flows, and often take the caller back after the agent.

## SIP address

SIP is the internet phone protocol. A SIP address is a phone address that starts with `sip:`, used to send a call over the internet instead of to a phone number.

Vapi for CX can make a SIP address for an agent, in the form `sip:<name>@sip.vapi.ai`. Organizations in Vapi's EU region use `sip.eu.vapi.ai` instead. A phone system that can dial a SIP address can send calls to the agent this way.

- A SIP address always asks the system sending the call to sign in. Vapi for CX makes the username and password and shows them to you once. With the password switch off, any answer passes, but the sending system must still answer the sign-in. A system that cannot answer a sign-in cannot use a SIP address.
- Caller details can travel with the call as headers whose names start with `X-`. The agent can read them.
- Vapi cannot ring a SIP address itself, so to check one you send a call to it from your phone system.

A trunk is a standing SIP connection between a carrier or phone system and Vapi. Vapi for CX has no trunk form: a trunk is set up in Vapi's dashboard (**Connect in Vapi**).

## UUI

UUI (User-to-User Information) is a small data field that many contact centers pass along with a call, often to say who the caller is or why they called. Vapi does not read UUI on calls in to an agent. Where a contact center can send caller details as `X-` headers instead, the agent can read those.
