Connect a phone line to an agent in [Vapi for CX](https://cx.vapi.ai) so that callers reach it, then add handoffs so that the agent can pass callers to your people. Each carrier, phone system, and contact center has its own page with the steps in both directions.

## Vapi for CX and Vapi's dashboard

Vapi for CX is the app at [cx.vapi.ai](https://cx.vapi.ai), where you build and run agents. An agent in Vapi for CX is an assistant in Vapi's dashboard. Vapi's dashboard is Vapi's own console, at [dashboard.vapi.ai](https://dashboard.vapi.ai). Both use the same login, and a phone number set up in one shows in the other.

## Connect a line from the setup checklist

You connect a phone line from the agent's setup checklist, in the step **Connect your phone line**.

Every agent starts with a free starter number from Vapi. Starter numbers are US only. **Keep the starter** finishes the step with that number.

After a line is connected, Vapi for CX asks you to **Call this number from your phone** (for a SIP address, **Send a call to it now**). The line shows as **Working** when that first call reaches the agent.

## What Vapi for CX connects

- **Twilio numbers:** connected with your Account SID and auth token. See the [Twilio page](/phone-systems/twilio).
- **Telnyx and Vonage numbers:** a Telnyx number connected with an API key, and a Vonage number with an API key and secret. See the [Telnyx](/phone-systems/telnyx) and [Vonage](/phone-systems/vonage) pages.
- **A business line forwarded to the agent:** forwarded from your phone company or office phone system. See [Call forwarding](/phone-systems/call-forwarding).
- **A SIP address for the agent:** for a phone system that can send calls over SIP. See [Own SIP or phone system](/phone-systems/own-phone-system) and [Jambonz](/phone-systems/jambonz).
- **A number already in Vapi:** a number you set up in Vapi's dashboard, for example on a SIP trunk, picked with **Use a number already in Vapi**. See the [Bandwidth](/phone-systems/bandwidth), [Plivo](/phone-systems/plivo), and [SignalWire](/phone-systems/signalwire) pages.
- **A contact center or office phone system:** the **A contact center** screen gives the agent's number for your contact center or phone system to forward calls to. See the pages for [Microsoft Teams](/phone-systems/microsoft-teams), [Google Voice](/phone-systems/google-voice), [Zoom](/phone-systems/zoom), [Dialpad](/phone-systems/dialpad), [RingCentral](/phone-systems/ringcentral), [8x8](/phone-systems/8x8), [Aircall](/phone-systems/aircall), [Genesys Cloud](/phone-systems/genesys), [Five9](/phone-systems/five9), [Amazon Connect](/phone-systems/amazon-connect), [Cisco Webex](/phone-systems/cisco-webex), [Talkdesk](/phone-systems/talkdesk), and [NICE CXone](/phone-systems/nice-cxone).

## Handing callers to people

Handoffs are set on the agent: on the **Call handling** tab, the **Handing callers to people** card has **Add a handoff**. Each handoff says when the agent should hand off and where the caller goes. There are three types:

- **Transfer to a phone number:** the agent passes the caller to a number of yours, such as a queue, a team, or a person.
- **Transfer to a SIP address:** the agent passes the caller to an address on your phone system. Where the line allows it, a summary and named details travel with the call.
- **Return the call to their system:** the agent says its last words and ends its part of the call, and your phone system or contact center carries on with the caller. Nothing tells your system why the agent handed the caller back, so the caller goes to your flow's default path.

Which types a line allows depends on the line the call arrives on.

**When "Return the call to their system" is offered.** This type is offered only when a phone system or contact center that takes calls back is linked to the agent's line, in **Organization settings**. Until a platform is linked, the type is grayed with the reason "Link a contact center or phone system to this agent's line in Organization settings first." The type is judged for all of the agent's lines together: when one of them has such a platform, it is offered, but it works only for calls on that line.

**A Twilio number on the agent.** A SIP handoff from a Twilio number is always dialed by Vapi, with no written summary or details. One handoff serves all of the agent's lines, so when the agent also answers on a Twilio number, its SIP handoffs are dialed on every line, with no summary or details.

**The agent leaves after the handoff.** Once the caller is handed off, the agent leaves the call and doesn't come back. **The agent waits until a person picks up** isn't offered on any line. The caller goes to whatever answers the number you hand off to: a person, voicemail, or a queue. On a Telnyx or Vonage number, if nobody answers, the call ends.

**Check a handoff.** Once the change with the handoff is live, call the line from your own phone and ask for a person. Vapi for CX shows "Handoff sent", then asks whoever answered to confirm that it arrived.

## SIP address

Session Initiation Protocol (SIP) is the protocol that sets up phone calls over the internet. A SIP address is an address that starts with `sip:` and sends a call over the internet instead of to a phone number.

Vapi for CX can make a SIP address for an agent, in the form `sip:<name>@sip.vapi.ai`. A phone system that can dial a SIP address can send calls to the agent this way.

- A SIP address always asks the system sending the call to sign in. Vapi for CX makes the username and password and shows them to you once. With **Only let calls in with this username and password** off, any username and password passes, but the sending system must still answer the sign-in. A system that can't answer a sign-in can't use a SIP address.
- Caller details can travel with the call as headers whose names start with `X-`. The agent can read them.
- Vapi can't ring a SIP address itself, so to check one you send a call to it from your phone system.

A SIP trunk is a standing SIP connection between a carrier or phone system and Vapi. Vapi for CX has no trunk form: you set up a SIP trunk in Vapi's dashboard.

## UUI

UUI (User-to-User Information) is a small data field that many contact centers pass along with a call, often to say who the caller is or why they called. Vapi doesn't read UUI on calls in to an agent. Where a contact center can send caller details as `X-` headers instead, the agent can read those.

## Limitations

- Organizations in Vapi's EU region are not supported in Vapi for CX yet.
