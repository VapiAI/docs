Create an assistant that can hold a conversation and end a call on request. This first assistant has no access to appointment data; the [tools guide](/gpt-live/tools) adds that capability.

## Prerequisites

- A Vapi organization with GPT-Live enabled.
- A microphone and a browser with microphone permission.
- A Vapi private API key for the API method. Keep it on your server or local machine.
- If you supply an OpenAI key, access to GPT-Live and the selected reasoner model on that key.

## Create the assistant

Choose either method. Both create a saved assistant that you can test in the dashboard.

<Tabs>
<Tab title="Dashboard">
<Steps>
<Step title="Create an assistant">
Open [Assistants](https://dashboard.vapi.ai/assistants), select **Create Assistant**, and choose **GPT-Live** in the assistant configuration.
</Step>
<Step title="Configure the conversation">
Choose Marin as the voice. In **Speaker**, enter:

```text
You explain appointment scheduling. Speak clearly and briefly.
Availability checks and booking are not connected yet.
Delegate requests to end the call. Do not claim to have checked or changed a booking.
```

In **Reasoner**, enter:

```text
When the caller asks to finish, call endCall.
No availability or booking tools are configured. Do not invent appointment results.
```

Keep or add the `endCall` tool in the assistant's tools.
</Step>
<Step title="Set a greeting">
Set the first message to “Hello. I can help explain appointment scheduling. What would you like to know?” Configure the assistant to speak first.
</Step>
<Step title="Publish the assistant">
Select **Publish** and complete the publication flow. Keep the assistant ID for later API requests.
</Step>
</Steps>
</Tab>
<Tab title="API" language="bash">
<Steps>
<Step title="Save the configuration">
Save this JSON as `assistant.json`:

```json title="assistant.json"
{
  "name": "Appointment assistant",
  "model": {
    "provider": "openai",
    "model": "gpt-live-1",
    "speaker": {
      "instructions": "You are an appointment assistant. Speak clearly and briefly. Ask a short question when the request is unclear. You cannot check availability or book appointments yet. Delegate requests to end the call. Do not claim to have checked or changed a booking."
    },
    "reasoner": {
      "model": "gpt-5.6-terra",
      "reasoningEffort": "low",
      "instructions": "Handle delegated requests using the available tools. When the caller asks to finish, call endCall. No availability or booking tools are configured. Do not invent appointment results."
    },
    "tools": [
      {
        "type": "endCall"
      }
    ]
  },
  "voice": {
    "provider": "openai",
    "voiceId": "marin"
  },
  "firstMessageMode": "assistant-speaks-first",
  "firstMessage": "Hello. I can help explain appointment scheduling. What would you like to know?",
  "maxDurationSeconds": 600
}
```
</Step>
<Step title="Create the assistant">
Set `VAPI_PRIVATE_API_KEY` to your Vapi private API key, then send the configuration:

```bash
curl --fail-with-body https://api.vapi.ai/assistant \
  -H "Authorization: Bearer $VAPI_PRIVATE_API_KEY" \
  -H "Content-Type: application/json" \
  --data-binary @assistant.json
```

Keep the returned `id`. This request uses the [Create Assistant endpoint](/api-reference/assistants/create).
</Step>
</Steps>
</Tab>
</Tabs>

## Test the conversation

Open the saved assistant in the dashboard and select **Talk**. Allow microphone access when prompted.

Try these exchanges:

| Say | Expected outcome |
| --- | --- |
| “What can you help with?” | The assistant explains its limited appointment role. |
| “Can you book Friday?” | It explains that booking is not connected; it does not invent a reservation. |
| Interrupt a long answer with “Keep it brief.” | It adapts the conversation to the request. |
| “That's all. Please end the call.” | It delegates the request and invokes `endCall`. |

Check both the conversation and the call record. A spoken goodbye alone does not prove that the call ended. You can also end the web call with the dashboard's call controls.

## Continue building

Add an [availability lookup tool](/gpt-live/tools), then update both prompts to describe the new capability. See [Configuration and compatibility](/gpt-live/configuration) for phone calls and raw WebSocket audio.
