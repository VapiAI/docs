## Choose an integration

The CLI provides setup commands for the v2 MCP connection and public agent skills:

| Command | What it sets up | Authentication |
| --- | --- | --- |
| `vapi mcp setup` | The Vapi **v2 API MCP server**, for managing assistants, calls, phone numbers, and other resources | Your current Vapi API key |
| `vapi skills setup` | Public **agent skills** from `VapiAI/skills`, installed for your coding agent | No API key to install |

<Note>
  This command layout requires the CLI release containing the MCP setup update. Earlier releases use `vapi mcp setup` to configure the local `@vapi-ai/mcp-docs-server`. See [Migrate existing setup](#migrate-existing-setup).
</Note>

## Set up API tools

Install the [Vapi CLI](/cli) and Node.js with npm, then sign in and configure your IDE:

```bash
vapi login
vapi mcp setup
```

The command detects supported IDEs and prompts you to select which ones to configure. To configure one directly:

```bash
vapi mcp setup cursor
vapi mcp setup windsurf
vapi mcp setup vscode
```

The CLI adds a server named `vapi` that connects to `https://mcp-v2.vapi.ai/api/mcp` using **Streamable HTTP**. It reads your current API key from CLI configuration, `VAPI_API_KEY`, or an explicit `--api-key` flag, and stores it in the user MCP configuration. Keep this file private; on POSIX systems setup writes it with mode `0600`. Re-run setup after changing accounts or rotating the key.

Restart your IDE, enable the `vapi` server in its MCP settings, and start a new chat. See the [Vapi MCP Server guide](/sdk/mcp-server) for available API tools.

### Documentation through the same connection

Documentation search is planned through the v2 MCP server, which will proxy requests to the documentation backend. The CLI configures the v2 connection; no separate documentation MCP connection is needed. Tool availability depends on the deployed v2 server.

Install public agent skills separately for your agent's native discovery and activation behavior.

## Install public agent skills

```bash
vapi skills setup
```

This runs `npx -y skills add VapiAI/skills`. The installer lets you choose skills and coding agents. It installs into the current project by default; use `--global` for user-wide installation. Node.js **22.20 or later** with npm is required.

Installer options are forwarded:

```bash
vapi skills setup --agent cursor --skill create-assistant
vapi skills setup --global --agent claude-code --yes
```

This installs skill files; it does not configure an MCP server. See the [public skills repository](https://github.com/VapiAI/skills) for workflows and agent support.

## What MCP setup writes

`vapi mcp setup` uses `mcp-remote` as a local stdio adapter to the hosted server. The remote connection is restricted to **Streamable HTTP** with `--transport http-only`; legacy SSE fallback is disabled. Node.js and `npx` must be available to your IDE.

Setup creates or updates the `vapi` entry and preserves unrelated settings.

| IDE | User configuration file |
| --- | --- |
| Cursor | `~/.cursor/mcp.json` |
| Windsurf | `~/.codeium/windsurf/mcp_config.json` |
| VS Code on macOS | `~/Library/Application Support/Code/User/mcp.json` |
| VS Code on Linux | `$XDG_CONFIG_HOME/Code/User/mcp.json`, defaulting to `~/.config/Code/User/mcp.json` |
| VS Code on Windows | `%APPDATA%/Code/User/mcp.json` |

`~` represents your home directory. MCP setup is per user; skills installation is per project unless you pass `--global`.

### Example: Cursor API configuration

```json
{
  "mcpServers": {
    "vapi": {
      "command": "npx",
      "args": [
        "-y",
        "mcp-remote",
        "https://mcp-v2.vapi.ai/api/mcp",
        "--transport",
        "http-only",
        "--header",
        "Authorization: Bearer ${VAPI_API_KEY}"
      ],
      "env": {
        "VAPI_API_KEY": "YOUR_VAPI_API_KEY"
      }
    }
  }
}
```

Windsurf uses the same JSON shape. VS Code uses a top-level `servers` object and includes `"type": "stdio"` on each entry.

On Windows, the adapter command is `cmd` with `args` starting with `["/c", "npx", ...]`.

## Migrate existing setup

Earlier CLI releases configured the in-house local docs package under an entry named `vapi`. To switch to the new layout:

```bash
# Replace the old vapi entry with the authenticated v2 API connection
vapi mcp setup
```

`vapi mcp status` identifies the legacy local docs entry rather than reporting it as an API connection. Older CLI releases wrote VS Code configuration to `~/.vscode/mcp.json`; the updated CLI writes to VS Code's user configuration directory.

## Check configuration

```bash
vapi mcp status
```

This command inspects configuration files without connecting to a server or printing API keys. Check your IDE's MCP status and logs to confirm that the server starts successfully.

To remove the integration, delete its `vapi` entry from the relevant configuration file and restart the IDE.
