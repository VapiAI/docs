This page shows the server URL and authentication for common MCP providers, with links to each provider's own setup steps. To create the MCP tool itself, see [MCP tools](/tools/mcp).

Each provider controls which tools its server exposes. Vapi adds every tool the server lists, so limit the tools at the provider. For more information, see [Choose which tools the voice agent gets](/tools/mcp/configure#choose-which-tools-the-voice-agent-gets).

## Zapier

Zapier's MCP server supports Streamable HTTP only. Vapi connects with a connection token.

<Steps>
  <Step title="Create the server">
    Create a server at [Zapier MCP](https://mcp.zapier.com) and add the apps and actions the voice agent can use. See [How Zapier MCP servers work](https://docs.zapier.com/mcp/overview/how-servers-work).
  </Step>
  <Step title="Generate a connection token">
    Generate a connection token for the server. Zapier shows the token only once, and generating a new one stops the old one from working. See [How connections work](https://docs.zapier.com/mcp/overview/how-connections-work).
  </Step>
  <Step title="Connect the MCP tool">
    On the MCP tool, set the server URL to `https://mcp.zapier.com/api/v1/connect` and add this header:

    ```text
    Authorization: Bearer YOUR_ZAPIER_CONNECTION_TOKEN
    ```
  </Step>
</Steps>

For more information, see Zapier's [Connect any other MCP client](https://docs.zapier.com/mcp/get-started/connect/other).

## Composio

<Steps>
  <Step title="Create the server">
    Create an MCP server for the toolkit you need and generate its URL. See [Single toolkit MCP](https://docs.composio.dev/docs/single-toolkit-mcp).
  </Step>
  <Step title="Connect the MCP tool">
    On the MCP tool, set the server URL to the generated URL and add this header:

    ```text
    x-api-key: YOUR_COMPOSIO_API_KEY
    ```
  </Step>
</Steps>

Use the URL Composio generates. Don't build it yourself.

## Make

Make's MCP server can expose your active, on-demand scenarios as tools. It can also expose tools that manage your Make account, depending on the API key's scopes.

<Warning>
Scenario access control applies to scenario tools, not management tools. A broadly scoped API key can expose management tools that can change Make resources. Grant no management scopes unless the voice agent needs them.
</Warning>

<Steps>
  <Step title="Prepare the scenarios">
    Define the inputs and outputs for each scenario, then set its schedule to **On demand**.
  </Step>
  <Step title="Create an API key">
    In Make, open **Profile** > **API access**, click **+ API token**, and create an API key with the `mcp:use` scope and only the other scopes the voice agent needs. See [Connect using API key](https://developers.make.com/mcp-server/connect-using-api-key).
  </Step>
  <Step title="Connect the MCP tool">
    Set the server URL to `https://<MAKE_ZONE>/mcp/v2`, where `<MAKE_ZONE>` is your organization's zone, such as `eu2.make.com`. Add this header:

    ```text
    Authorization: Bearer YOUR_MAKE_API_KEY
    ```
  </Step>
  <Step title="Limit scenario access (optional)">
    By default, the key can use every active, on-demand scenario in your Make organizations. To limit it to an organization, team, or specific scenarios, use the connection URL from Make's [scenarios as tools access control](https://developers.make.com/mcp-server/connect-using-api-key/scenarios-as-tools-access-control). That URL includes the API key, so treat it as a secret.
  </Step>
</Steps>
