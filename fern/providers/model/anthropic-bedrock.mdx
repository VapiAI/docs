**What is Anthropic Bedrock?**

Amazon Bedrock is a fully managed service that provides access to foundation models from leading AI companies, including Anthropic's Claude models. With Bedrock, you can use Claude models through AWS infrastructure, benefiting from enterprise-grade security, regional data residency, and seamless integration with your existing AWS environment.

**Custom Anthropic Bedrock Integration with Vapi:**

Vapi's Anthropic Bedrock integration allows you to connect your own AWS Bedrock resources to power voice assistants with Claude models. This enables you to maintain full control over your AWS billing, use your own rate limits, and ensure data stays within your AWS environment.

## Language model

For the current Anthropic Claude models available through Amazon Bedrock, see [Anthropic models in the Amazon Bedrock documentation](https://docs.aws.amazon.com/bedrock/latest/userguide/model-cards-anthropic.html). Model availability varies by AWS Region.

Some Claude models are available through Bedrock's global cross-Region inference profiles. Their model IDs start with `global.`. A global profile can route requests to supported commercial AWS Regions worldwide.

To use a global profile, grant access to the profile, its foundation model in the source Region, and its global foundation model ARN. See the [`AnthropicBedrockModel` fields](/api-reference/assistants/create#request.body.model.AnthropicBedrock) for the model IDs Vapi accepts.

For more information, see the following Amazon Bedrock documentation:

- [Cross-Region inference](https://docs.aws.amazon.com/bedrock/latest/userguide/cross-region-inference.html)
- [Global cross-Region inference](https://docs.aws.amazon.com/bedrock/latest/userguide/global-cross-region-inference.html), including its IAM policy requirements
- [Supported Regions and models for inference profiles](https://docs.aws.amazon.com/bedrock/latest/userguide/inference-profiles-support.html)

### Prerequisites

Before configuring Anthropic Bedrock with Vapi, ensure you have:

- An active AWS account with Bedrock access enabled
- Model access granted for Anthropic Claude models in your Bedrock console
- IAM permissions to create roles and policies

## Configuration steps

<Steps>
  <Step title="Create an IAM Role in AWS">
    Create a new IAM role that Vapi will assume to access your Bedrock resources.

    1. Go to the **IAM Console** in AWS
    2. Navigate to **Roles** and click **Create role**
    3. Select **Custom trust policy** as the trusted entity type
    4. Add the trust policy from the next step

    <Note>
    Choose a descriptive name for your role, such as `VapiBedrockRole`, so you can easily identify its purpose.
    </Note>
  </Step>

  <Step title="Attach the Trust Policy">
    Configure the trust policy to allow Vapi's AWS account to assume this role.

    An External ID is optional. If you use one, enter the same unique value in the trust policy and Vapi credential. Both examples trust Vapi's production AWS account.

    For more information about these policies, see AWS's guides to [creating a role with a custom trust policy](https://docs.aws.amazon.com/IAM/latest/UserGuide/id_roles_create_for-custom.html) and [using External IDs for third-party access](https://docs.aws.amazon.com/IAM/latest/UserGuide/id_roles_common-scenarios_third-party.html).

    <Tabs>
      <Tab title="With External ID">
        Replace `YOUR_UNIQUE_EXTERNAL_ID` with a unique value before use. AWS recommends an External ID for third-party cross-account access.

        ```json title="Trust policy with External ID"
        {
          "Version": "2012-10-17",
          "Statement": [
            {
              "Effect": "Allow",
              "Principal": {
                "AWS": "arn:aws:iam::533267069243:root"
              },
              "Action": "sts:AssumeRole",
              "Condition": {
                "StringEquals": {
                  "sts:ExternalId": "YOUR_UNIQUE_EXTERNAL_ID"
                }
              }
            }
          ]
        }
        ```
      </Tab>
      <Tab title="Without External ID">
        Use this policy only if you do not require an External ID for the role. It does not check which Vapi customer the request is for.

        ```json title="Trust policy without External ID"
        {
          "Version": "2012-10-17",
          "Statement": [
            {
              "Effect": "Allow",
              "Principal": {
                "AWS": "arn:aws:iam::533267069243:root"
              },
              "Action": "sts:AssumeRole"
            }
          ]
        }
        ```
      </Tab>
    </Tabs>
  </Step>

  <Step title="Attach the Permissions Policy">
    Use this policy when your Vapi credential Region is `us-east-1`. It allows Claude Haiku 5.5 through the US inference profile, which can route to `us-east-1`, `us-east-2`, or `us-west-2`. Replace `YOUR_AWS_ACCOUNT_ID` with your AWS account ID before creating the policy.

    ```json title="Permissions policy: us-east-1"
    {
      "Version": "2012-10-17",
      "Statement": [
        {
          "Effect": "Allow",
          "Action": [
            "bedrock:InvokeModel",
            "bedrock:InvokeModelWithResponseStream"
          ],
          "Resource": "arn:aws:bedrock:us-east-1:YOUR_AWS_ACCOUNT_ID:inference-profile/us.anthropic.claude-haiku-5-5"
        },
        {
          "Effect": "Allow",
          "Action": [
            "bedrock:InvokeModel",
            "bedrock:InvokeModelWithResponseStream"
          ],
          "Resource": [
            "arn:aws:bedrock:us-east-1::foundation-model/anthropic.claude-haiku-5-5",
            "arn:aws:bedrock:us-east-2::foundation-model/anthropic.claude-haiku-5-5",
            "arn:aws:bedrock:us-west-2::foundation-model/anthropic.claude-haiku-5-5"
          ],
          "Condition": {
            "StringEquals": {
              "bedrock:InferenceProfileArn": "arn:aws:bedrock:us-east-1:YOUR_AWS_ACCOUNT_ID:inference-profile/us.anthropic.claude-haiku-5-5"
            }
          }
        }
      ]
    }
    ```

    To adapt the policy, check the exact profile ID, supported source Regions, and destination Regions in the [AWS Claude Haiku 5.5 model card](https://docs.aws.amazon.com/bedrock/latest/userguide/model-card-anthropic-claude-haiku-5-5.html). You can also call [GetInferenceProfile](https://docs.aws.amazon.com/bedrock/latest/userguide/inference-profiles-view.html) from your source Region with an AWS identity that has `bedrock:GetInferenceProfile` permission. Update the profile ARN, foundation model ARNs, and `bedrock:InferenceProfileArn` condition together. Check the [`AnthropicBedrockModel` fields](/api-reference/assistants/create#request.body.model.AnthropicBedrock) for the model IDs Vapi accepts.

    For more information about the required resources, see AWS's [inference profile prerequisites](https://docs.aws.amazon.com/bedrock/latest/userguide/inference-profiles-prereq.html). Global profiles require a different policy shape; see AWS's [global cross-Region inference guidance](https://docs.aws.amazon.com/bedrock/latest/userguide/global-cross-region-inference.html).

    Before attaching the policy, use [IAM Access Analyzer policy validation](https://docs.aws.amazon.com/IAM/latest/UserGuide/access-analyzer-policy-validation.html) to review its syntax and permissions. Other policies and service control policies can also affect the role's effective access.

    To attach the policy:

    1. In the IAM Console, go to **Policies** and click **Create policy**
    2. Select **JSON** and paste the policy
    3. Name the policy (e.g., `VapiBedrockInvokePolicy`)
    4. Attach the policy to your IAM role
  </Step>

  <Step title="Create the Vapi Credential">
    Use the Vapi API to create a credential with your AWS role information:

    ```bash title="Create Credential via API"
    curl -X POST "https://api.vapi.ai/credential" \
      -H "Authorization: Bearer YOUR_VAPI_API_KEY" \
      -H "Content-Type: application/json" \
      -d '{
        "provider": "anthropic-bedrock",
        "region": "us-east-1",
        "authenticationPlan": {
          "type": "aws-sts",
          "roleArn": "arn:aws:iam::YOUR_AWS_ACCOUNT_ID:role/VapiBedrockRole",
          "externalId": "YOUR_UNIQUE_EXTERNAL_ID"
        }
      }'
    ```

    | Field | Description |
    |-------|-------------|
    | `provider` | Must be `anthropic-bedrock` |
    | `region` | AWS region where Bedrock is enabled (e.g., `us-east-1`) |
    | `authenticationPlan.type` | Must be `aws-sts` for role assumption |
    | `authenticationPlan.roleArn` | The ARN of the IAM role you created |
    | `authenticationPlan.externalId` | Optional; include only with the matching External ID trust policy |

    If you choose the trust policy without an External ID, omit the `externalId` field from the request.
  </Step>
</Steps>

## Troubleshooting

### Common error: "Access Denied"
- **Cause**: The IAM role trust policy doesn't allow Vapi to assume the role
- **Solution**: Verify the trust policy includes Vapi's AWS account ID (`533267069243`) and the correct External ID

### Common error: "Invalid External ID"
- **Cause**: The External ID in your trust policy doesn't match the one in your Vapi credential
- **Solution**: Ensure the `externalId` value in your Vapi credential exactly matches the `sts:ExternalId` in your IAM trust policy. If you're not using an External ID, remove the `Condition` block from your trust policy

### Common error: "Model access denied"
- **Cause**: The IAM permissions policy doesn't grant access to the requested model, or model access isn't enabled in Bedrock
- **Solution**:
  1. Verify the permissions policy includes the correct model ARNs
  2. Ensure you've enabled access to the model in the AWS Bedrock console

### Common error: "Region not supported"
- **Cause**: The specified region doesn't have Bedrock or the requested model available
- **Solution**: Use a supported region such as `us-east-1`, `us-west-2`, or `eu-west-1`
