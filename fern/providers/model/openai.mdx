OpenAI provides language models for Vapi voice agents.

You can use OpenAI through Vapi's default integration, or connect your own account in [Integrations](/providers/integrations).

## Supported capability

| Capability | Provider value |
| --- | --- |
| Language model | `openai` |

## Language model

Set `model.provider` to `openai` and `model.model` to a GPT model.

```bash
curl -X PATCH "https://api.vapi.ai/assistant/ASSISTANT_ID" \
  -H "Authorization: Bearer $VAPI_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": { "provider": "openai", "model": "gpt-4.1" }
  }'
```

For additional API configuration options, review the [`OpenAIModel` fields](/api-reference/assistants/create#request.body.model.OpenAIModel) in the Create Assistant API reference.

### Regional models

To keep model requests in one region, set `model.model` to a region-qualified model ID. The value after the colon is the Azure region that serves the request. You can also select these IDs in the model picker for assistants, squads, evals, and structured outputs.

```bash
curl -X PATCH "https://api.vapi.ai/assistant/ASSISTANT_ID" \
  -H "Authorization: Bearer $VAPI_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": { "provider": "openai", "model": "gpt-5.4:eastus2" }
  }'
```

If you've added an [Azure OpenAI credential](/providers/model/azure-openai) for the selected region, Vapi routes the request through it. Otherwise, Vapi uses its own deployment in that region. A region-qualified request never falls back to another region.

## Service tier

For latency-sensitive assistants, you can run supported OpenAI models in OpenAI's faster processing tier. In the assistant's model settings, turn on **Priority processing**. Through the API, set `model.serviceTier` on a supported model.

| Value | Behavior |
| --- | --- |
| `fast` | Requests OpenAI's fast processing tier for lower latency, billed at OpenAI's fast-tier rates. If OpenAI downgrades the request under load, the call is billed at standard rates. The **Priority processing** switch sets this value. |
| `auto` | Uses the service tier configured for your OpenAI project. |
| `default` | Standard processing and billing. |

`serviceTier` applies only to models that support fast processing: `gpt-6-luna`, `gpt-5.6-sol`, `gpt-5.6-terra`, `gpt-5.6-luna`, and `gpt-5.5`. It is ignored for other models. When unset, Vapi uses the service tier configured for your OpenAI project. See [OpenAI's pricing](https://openai.com/api/pricing) for fast-tier rates, and the [`OpenAIModel` fields](/api-reference/assistants/create#request.body.model.OpenAIModel) in the Create Assistant API reference.

```bash
curl -X PATCH "https://api.vapi.ai/assistant/ASSISTANT_ID" \
  -H "Authorization: Bearer $VAPI_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": { "provider": "openai", "model": "gpt-5.6-sol", "serviceTier": "fast" }
  }'
```

When OpenAI reports the tier it served for a Fast-mode request, the model's cost in the call includes a `serviceTierBreakdown` that splits usage by served tier.
