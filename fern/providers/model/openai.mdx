OpenAI provides language models for Vapi voice agents.

You can use OpenAI through Vapi's default integration, or connect your own account in [Integrations](/providers/integrations).

## Supported capability

| Capability | Provider value |
| --- | --- |
| Language model | `openai` |

## Language model

Set `model.provider` to `openai` and `model.model` to a GPT model.

```bash
curl -X PATCH "https://api.vapi.ai/assistant/ASSISTANT_ID" \
  -H "Authorization: Bearer $VAPI_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": { "provider": "openai", "model": "gpt-4.1" }
  }'
```

For additional API configuration options, review the [`OpenAIModel` fields](/api-reference/assistants/create#request.body.model.OpenAI) in the Create Assistant API reference.

### Regional models

To keep model requests in one region, set `model.model` to a region-qualified model ID. The value after the colon is the Azure region that serves the request. You can also select these IDs in the model picker for assistants, squads, evals, and structured outputs.

```bash
curl -X PATCH "https://api.vapi.ai/assistant/ASSISTANT_ID" \
  -H "Authorization: Bearer $VAPI_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": { "provider": "openai", "model": "gpt-5.4:eastus2" }
  }'
```

If you've added an [Azure OpenAI credential](/providers/model/azure-openai) for the selected region, Vapi routes the request through it. Otherwise, Vapi uses its own deployment in that region. A region-qualified request never falls back to another region.

## Prompt caching

Prompt caching lets OpenAI reuse the unchanged beginning of a prompt, such as your assistant's instructions and tool definitions, instead of processing it again on every request. Cache hits can reduce input-token costs and latency, but are not guaranteed.

For supported GPT-4.1 and GPT-5.x models, open the assistant's model **Advanced settings** in the Dashboard to configure **Prompt cache retention** and **Prompt cache key**. Check the Dashboard or the [`OpenAIModel` fields](/api-reference/assistants/create#request.body.model.OpenAI) for the current supported model list.

- **`promptCacheKey`**: An optional hint to help OpenAI reuse matching prompt prefixes across requests. It does not store a prompt or guarantee a cache hit. In the standard assistant model configuration, Vapi leaves this unset unless you provide it; it does not generate a key automatically.
- **`promptCacheRetention`**: Choose `in_memory` for OpenAI's in-memory cache policy or `24h` to keep cached prefixes available for up to 24 hours on models that support extended caching.

Both settings are unset by default. For these models, omitting retention uses OpenAI's default `in_memory` policy; leaving the key unset does not disable automatic prompt caching.

For example, include these fields in your assistant's model configuration:

```json
{
  "model": {
    "provider": "openai",
    "model": "gpt-4.1",
    "promptCacheKey": "support-assistant-v1",
    "promptCacheRetention": "24h"
  }
}
```

## Reasoning effort

Reasoning models think before they answer. Set `model.reasoningEffort` to control how much. A lower effort reduces latency and cost, which suits most voice calls. A higher effort can help with harder tasks.

Each model accepts only the efforts OpenAI supports for it:

| Model | Accepted values |
| --- | --- |
| GPT 6 Luna | `none`, `low`, `medium`, `high`, `xhigh` |
| GPT 5.6 Sol, GPT 5.6 Terra, GPT 5.6 Luna | `none`, `low`, `medium`, `high`, `xhigh` |
| GPT 5.4, GPT 5.4 Mini, GPT 5.2 | `none`, `low`, `medium`, `high`, `xhigh` |
| GPT 5, GPT 5 Mini, GPT 5 Nano | `minimal`, `low`, `medium`, `high` |

Region-qualified model IDs, such as `gpt-5.6-luna:westus3`, accept the same values as the base model. Saving a value the model doesn't support returns a `400` error.

```bash
curl -X PATCH "https://api.vapi.ai/assistant/ASSISTANT_ID" \
  -H "Authorization: Bearer $VAPI_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": { "provider": "openai", "model": "gpt-5.6-luna", "reasoningEffort": "none" }
  }'
```

In the Dashboard, the **Reasoning effort** setting appears for GPT 6 models. For other models, set `reasoningEffort` through the API.

## Service tier

For latency-sensitive assistants, you can run supported OpenAI models in OpenAI's faster processing tier. In the assistant's model settings, turn on **Priority processing**. Through the API, set `model.serviceTier` on a supported model.

| Value | Behavior |
| --- | --- |
| `fast` | Requests OpenAI's fast processing tier for lower latency, billed at OpenAI's fast-tier rates. If OpenAI downgrades the request under load, the call is billed at standard rates. The **Priority processing** switch sets this value. |
| `auto` | Uses the service tier configured for your OpenAI project. |
| `default` | Standard processing and billing. |

`serviceTier` applies only to models that support fast processing: `gpt-6-luna`, `gpt-5.6-sol`, `gpt-5.6-terra`, `gpt-5.6-luna`, and `gpt-5.5`. It is ignored for other models. When unset, Vapi uses the service tier configured for your OpenAI project. See [OpenAI's pricing](https://openai.com/api/pricing) for fast-tier rates, and the [`OpenAIModel` fields](/api-reference/assistants/create#request.body.model.OpenAI) in the Create Assistant API reference.

```bash
curl -X PATCH "https://api.vapi.ai/assistant/ASSISTANT_ID" \
  -H "Authorization: Bearer $VAPI_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": { "provider": "openai", "model": "gpt-5.6-sol", "serviceTier": "fast" }
  }'
```

When OpenAI reports the tier it served for a Fast-mode request, the model's cost in the call includes a `serviceTierBreakdown` that splits usage by served tier.
