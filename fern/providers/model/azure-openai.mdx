**What is Azure OpenAI?**

Azure OpenAI Service provides REST API access to OpenAI's language models. These models can be easily adapted to your specific task with fine-tuning, offering enterprise-grade security, responsible AI practices, and regional availability.

**Custom Azure OpenAI Integration with Vapi:**

With Vapi's Azure OpenAI integration, you can connect your own Azure OpenAI instances to leverage your custom rate limits, regional deployments, and specific configurations. This enables you to use your Azure OpenAI resources directly while maintaining full control over billing, usage limits, and data residency.

## Language model

For additional API configuration options, see [Create Assistant](/api-reference/assistants/create) in the API reference.

### Prerequisites

Before configuring Azure OpenAI with Vapi, ensure you have:

- An active Azure subscription
- Azure OpenAI Service resource deployed
- Model deployments configured in your Azure OpenAI instance
- API keys and endpoint information from your Azure OpenAI resource

## Credential Settings

You can configure your Azure OpenAI credentials in the Vapi dashboard. Select **Integrations** in the sidebar, then select **Azure OpenAI** under **Model Providers**.

| Setting | Description | Required |
|---------|-------------|----------|
| **Provider** | Select "Azure OpenAI" | ✅ |
| **Models** | List of supported Vapi model IDs | ✅ |
| **Region** | Azure region where your OpenAI resource is deployed | ✅ |
| **OpenAI Endpoint** | Base Azure OpenAI endpoint URL (e.g., `https://your-resource.openai.azure.com`) | ✅ |
| **OpenAI Key** | API key for your Azure OpenAI resource | ✅ |
| **OCP-APIM-Subscription-Key** | API Management subscription key (optional and may be left blank) | ❌ |

## Important Configuration Notes

### Model and Deployment Names

Your credential's `models` must use Vapi's supported model IDs. By default, Vapi uses each model ID as the Azure deployment name. To use a custom name, set `deployments` through the [credential API](/api-reference/credentials/create):

```json
{
  "provider": "azure-openai",
  "models": ["gpt-5.6-sol-2026-07-09"],
  "deployments": [
    {"model": "gpt-5.6-sol-2026-07-09", "name": "my-custom-gpt"}
  ]
}
```

This is a credential configuration excerpt; include your region, endpoint and key when creating the credential. The dashboard preserves saved mappings but cannot edit deployment names.

Once `deployments` has any entries, include one for every model in `models`, even when its deployment name equals the model ID. Names must be 1–64 letters, digits, hyphens, underscores or periods, starting with a letter or digit. Omit the field to use model IDs as deployment names on a new credential. To clear existing mappings, update the credential with `"deployments": []`; omitting the field on an update keeps saved mappings.

If multiple keys cover the same region and model, set `credentialIds` on the assistant to select the intended key. Otherwise, Vapi uses the first matching key.

### Regional model routing

To route an assistant's model requests to a specific Azure region, set `model.provider` to `openai` and set `model.model` to one of the region-qualified model IDs below. The value after the colon is the Azure region. These are assistant model IDs, not Azure deployment names.

When the request uses an Azure OpenAI credential configured for the selected region, Vapi routes through that credential. Otherwise, Vapi uses its managed Azure deployment in that region. Vapi does not send a region-pinned request through an out-of-region fallback.

```bash
curl -X PATCH "https://api.vapi.ai/assistant/ASSISTANT_ID" \
  -H "Authorization: Bearer $VAPI_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": {
      "provider": "openai",
      "model": "gpt-5.4:eastus2"
    }
  }'
```

### UK South BYOK routes

UK South routes require your own Azure OpenAI credential with `region: "uk"` and the matching model in `models`. Vapi does not provide managed UK deployments or `:uk` model pins. Use an unqualified assistant model ID, such as `gpt-6-luna`, with `model.provider: "openai"`, and select the key with the assistant's `credentialIds`.

These UK routes support Chat Completions only, not the Responses API:

- `gpt-6-luna`
- `gpt-5.6-sol-2026-07-09`, `gpt-5.6-terra-2026-07-09`, `gpt-5.6-luna-2026-07-09`
- `gpt-5.5`, `gpt-5.4`, `gpt-5.4-mini`, `gpt-5.4-nano`

The IDs above are credential model IDs; for GPT 5.6 assistant models, use the corresponding unqualified name, such as `gpt-5.6-luna`. Custom deployment names still use `deployments` mappings.

### Endpoint URL Format

<Tip>
Use only the **base endpoint URL** from your Azure OpenAI resource, not the full completions URL.
</Tip>

**Correct format:**
```text
https://your-resource-name.openai.azure.com
```

**Incorrect format:**
```text
https://your-resource-name.openai.azure.com/openai/deployments/gpt-5.6-sol-2026-07-09/chat/completions?api-version=2024-11-20
```

### API Management Subscription Key

The `OCP-APIM-Subscription-Key` field is optional and can be left blank in most configurations. Only include this if your Azure OpenAI resource is behind Azure API Management and specifically requires this header.

## Configuration Steps

<Steps>
  <Step title="Gather Azure OpenAI Details">
    From your Azure OpenAI resource in the Azure portal, collect:
    - Base endpoint URL
    - API key (from Keys and Endpoint section)
    - Deployment names
    - Region
  </Step>

  <Step title="Verify Deployment Names">
    Select the supported model IDs served by your deployments. If a deployment's name differs from its model ID, add a `deployments` mapping through the credential API.
  </Step>

  <Step title="Configure in Vapi Dashboard">
    Select **Integrations** in the sidebar. Under **Model Providers**, select **Azure OpenAI** and add your configuration. Use the credential API to set custom deployment names.
  </Step>

  <Step title="Test Configuration">
    Create a test assistant using your Azure OpenAI model to verify the connection works correctly.
  </Step>
</Steps>

## Troubleshooting

### Common Error: "Resource not found"
- **Cause**: Incorrect endpoint URL or model deployment name
- **Solution**: Verify the base endpoint URL and ensure each `deployments` mapping names the deployment exactly as Azure shows it. Without mappings, deployment names must equal the selected model IDs.

### Common Error: "No model specified in request"
- **Cause**: The selected model has no matching deployment configuration
- **Solution**: Check the credential's `models` and `deployments`. Map each selected model to its Azure deployment name, or use matching model and deployment names without mappings.

### Common Error: "Couldn't Validate Azure OpenAI Credential"
- **Cause**: Invalid API key, incorrect endpoint, or network restrictions
- **Solution**: Verify API key, check endpoint URL format, and ensure network access
